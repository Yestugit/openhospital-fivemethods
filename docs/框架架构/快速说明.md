# 框架架构快速说明

更新：2026-11-01

## 1. 两条使用流程

独立接入 Agent：

```text
Agent → Memory 公共运行时 → 所选 Memory 方法
  observe / retrieve / learn       算法、存储与更新规则
```

运行测评：

```text
ExperimentConfig → ExperimentRunner.check() → evaluate() → results()
                         │
             ┌───────────┴───────────┐
        普通 Benchmark          OpenHospital 场景
       默认 QA 或用户 Agent     医生与医院环境适配
             └───────────┬───────────┘
                     Memory
```

Agent 保留对话、模型和工具调用逻辑。Memory 统一处理记忆操作与运行状态；测评入口组织案例、连续学习和结果记录。方法内部可采用不同算法、存储和更新时机。

## 2. Agent 使用的公共接口

| 接口 | 用途 |
|---|---|
| `Memory.check(config)` | 检查配置、依赖和方法条件 |
| `async with Memory(config)` | 创建并关闭一次 Memory 运行 |
| `await memory.observe(event)` | 上报交互事件；方法按自身规则处理 |
| `await memory.retrieve(query)` | 按需检索记忆 |
| `await memory.learn(episode)` | 提交一个完成的学习单元 |
| `await memory.evolve()` | 仅供需要 Agent 主动触发演化的方法调用 |
| `async with memory.read_only()` | 冻结记忆更新 |
| `await memory.save(path)` / `await memory.load(path)` | 保存或恢复状态 |

`flush()` 仅在方法要求提交缓冲工作时调用，不需要每次 `observe` 后执行。若 `learn` 省略经历中的 `events`，要关联先前 `observe` 的事件，双方需使用相同的 `episode_id`。

## 3. 测评入口

`ExperimentConfig` 配置方法、Benchmark、测评安排和输出；`ExperimentRunner` 提供统一的 `check(config)`、`evaluate(config)`、`results(path)`。

| protocol | 用途 |
|---|---|
| `streaming_memory` | 给定历史，逐题检索并回答 |
| `experience_train_test` | 先提交训练经历，再冻结测试 |
| `experience_learning_curve` | 连续训练，在指定检查点测试 |

普通 Benchmark 可使用内置 QA，也可提供 `agent(case, memory)`。OpenHospital 通过 `benchmark.kind="openhospital"` 进入场景适配，要求单个 Memory 方法和 `experience_learning_curve`；`OpenHospitalServices` 管理本地医院服务。`_ExperienceRunner` 是内部调度实现，用户不直接构造。

## 4. 关键数据

| 对象 | 含义 |
|---|---|
| `MemoryEvent` | 一条交互事件 |
| `MemoryContribution` | 检索到的记忆、组织后的上下文及来源 |
| `MemoryEpisode` | 提交给方法的学习单元，可按方法粒度包含不同经历 |
| `EpisodeResult` | 经历的执行、反馈和学习处理状态 |
| `BenchmarkCase` / `Prediction` | 测评输入与单例输出 |
| `EvaluationResult` | 测评预测、指标、失败和运行信息 |

## 5. 代码目录

| 目录 | 职责 |
|---|---|
| `core/` | 公共数据、能力、配置、注册和结果类型 |
| `runtime/` | Memory 运行时、公共历史、隔离和方法执行器 |
| `methods/` | 方法适配、配置声明和原生存储 |
| `benchmarks/` | 数据集读取、案例适配和原生评分 |
| `evaluation/` | 统一测评配置、调度、执行、结果与报告 |
| `integrations/openhospital/` | 医院场景适配、病例计划、医生执行和临床映射 |
| `providers/` | 模型与 Embedding 服务 |

Memory v2 已接入 Mem0、MemRL、MemoryOS；其余 11 个方法和 4 个控制基线仍待迁移。方法目录可被发现不代表已经可运行。

## 6. 推荐阅读顺序
