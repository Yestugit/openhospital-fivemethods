# RiseMem：关键对象、方法与数据结构

更新：2026-10-31

本文说明当前 RiseMem 框架的代码组织、公共对象、主要方法、核心数据结构和运行主线。阅读顺序建议为：先看 `Memory` 的公共流程，再看方法插件和数据结构，最后看评测层。

## 1. 框架定位与对象关系

RiseMem 是面向 Memory 方法集成、Agent 接入和 MemoryRSI 评测的工具箱。Agent 保留自己的提示组装、模型调用、工具执行和业务决策；RiseMem 提供记忆输入、检索、学习、演化、状态管理和评测调度。

```text
已有 Agent
  │
  ├─ 交互事件 ────────────────┐
  ├─ 检索查询 ── retrieve() ───┼─> Memory 运行时
  └─ 学习单元 ── learn() ──────┘       │
                                      ├─ 记录事件、经历和处理状态
                                      ├─ 检查方法能力、作用域和输入条件
                                      ├─ 调用选定的 Memory 方法
                                      ├─ 管理保存、恢复、冻结和资源统计
                                      └─ 返回 MemoryContribution 或 EpisodeResult
                                              │
                                      BaseMemoryMethod
                                              │
                         ┌────────────────────┼────────────────────┐
                         │                    │                    │
                   进程内方法           子进程方法             HTTP 服务方法
                         │                    │                    │
                         └──────────── 方法自己的算法与存储 ────────┘

评测层：Benchmark + EvaluationProtocol + ExperimentRunner
             │
             └─ 使用同一 Memory 公共接口组织训练、交互、评分、冻结评测和结果记录
```

公共接口的使用约定保持稳定：交互事件发生时调用 `observe`，需要记忆时调用 `retrieve`，一个学习单元完成时调用 `learn`。拥有独立演化机制的方法，按自己的周期或条件调用 `evolve`。方法内部可以采用即时写入、缓冲、批次更新或其他原生处理方式。

### 2.2 `Memory`：Agent 的主要运行对象

源码：[runtime/memory.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/runtime/memory.py)。

一个 `Memory` 对应一次选定方法的运行实例和独立运行目录。它连接 Agent、公共历史、方法实现和执行边界。

| 阶段 | 公共入口 | 作用 |
|---|---|---|
| 检查 | `Memory.check(config)` | 检查方法配置、依赖、服务、执行器和必要条件 |
| 创建 | `Memory(config)` | 根据 `method_id` 找到插件，分配运行目录并准备运行时 |
| 启动与关闭 | `async with Memory(config) as memory` | 进入时初始化方法，退出时关闭方法并处理方法要求的缓冲 |
| 记录事件 | `await memory.observe(event)` | 保存事件，并把事件交给方法的 `observe` 钩子 |
| 检索 | `await memory.retrieve(query, top_k=None, scope=None, extensions=None)` | 检查查询条件，调用方法检索并返回 `MemoryContribution` |
| 学习 | `await memory.learn(episode, scope=None)` | 补齐事件、校验学习单元和作用域，再交给方法学习 |
| 演化 | `await memory.evolve(scope=None, extensions=None)` | 供具有独立演化机制的方法按规定时机调用 |
| 缓冲处理 | `await memory.flush()` | 方法声明需要时处理待提交缓冲；不要求每次 `observe` 或 `learn` 后调用 |
| 保存与恢复 | `await memory.save(path)`、`await memory.load(path)` | 保存或恢复方法状态、公共历史、作用域和用量记录 |
| 冻结读取 | `async with memory.read_only()` | 在不改变持久记忆的条件下执行检索和测试 |
| 清理 | `await memory.reset(scope=None)` | 清理指定作用域的方法记忆和公共历史 |
| 特有核心操作 | `await memory.command(name, payload)` | 仅用于公共接口无法表达的方法核心操作 |
| 状态统计 | `memory.stats()` | 查看运行状态、事件数、经历数、操作追踪和资源用量 |

`Memory` 负责公共边界和状态管理。Agent 的模型、工具和业务评价由调用方完成；方法内部用于提取、检索或维护记忆的模型调用由方法通过服务对象使用。

### 2.3 `Memory` 的状态和边界

`MemoryState` 有四种状态：`created`、`started`、`closed`、`failed`。所有可写操作都会检查当前状态和 `read_only` 状态。方法操作异常、超时或执行边界不确定时，运行时会记录操作追踪，并将实例标记为需要恢复的新运行。

每个 `Memory` 默认拥有独立运行目录。相同 `Memory` 可以按顺序服务多个学习单元；每个学习单元由自己的 `episode_id` 区分，长期记忆可以在这些回合之间继续累积。

## 3. 方法集成对象

### 3.1 `BaseMemoryMethod`：方法实现契约

源码：[core/plugin.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/core/plugin.py)。

具体记忆方法实现 `BaseMemoryMethod`。运行时调用的方法侧接口为：

```python
class BaseMemoryMethod:
    async def setup(self, context: MethodContext) -> None: ...
    async def observe(self, event: MemoryEvent) -> None: ...
    async def retrieve(
        self, query, *, top_k, scope, extensions
    ) -> MemoryContribution: ...
    async def learn(
        self, episode: MemoryEpisode, *, observed_event_ids
    ) -> None: ...
    async def evolve(self, *, scope, extensions): ...
    async def flush(self) -> None: ...
    async def reset(self, scope) -> None: ...
    async def save(self) -> Mapping[str, Any]: ...
    async def load(self, state) -> None: ...
    async def command(self, name, payload): ...
    async def close(self) -> None: ...
```

这些方法属于方法实现侧。Agent 通过 `Memory` 调用公共入口，运行时负责作用域解析、输入检查、历史记录、只读保护、异常处理和结果转换。

### 3.2 `MethodPlugin`：方法创建和校验

`MethodPlugin` 为一种方法提供：

1. `descriptor`：方法的机器可读声明。
2. `create_method(config, services)`：根据方法配置创建 `BaseMemoryMethod` 实例。
3. `validate_config(config)`：检查方法参数。
4. `validate_input(operation, extensions)`：检查某个操作的额外输入。
5. `healthcheck(config, services)`：检查依赖包、源码、模型服务和其他运行条件。

方法通常通过自身目录的 `method.yaml` 声明信息，再由 `ManifestPlugin` 延迟加载实现模块。方法的简洁用户清单可以放在自身目录的 `usage.yaml`，用于说明参数、数据、接口时机和必要条件。

### 3.3 方法描述与能力

`MethodDescriptor` 描述方法身份和接入条件，常用字段包括：

| 字段 | 含义 |
|---|---|
| `method_id`、`name`、`summary` | 方法身份和简要说明 |
| `capabilities` | 支持的操作、模态、记忆形式、作用域、冻结模式等 |
| `config_schema` | 方法参数校验规则 |
| `requirements` | Python 包、模型服务、外部源码等依赖 |
| `storage` | 方法存储类型、路径参数和命名空间参数 |
| `commands` | 方法特有命令及其输入规则 |
| `input_schemas` | `observe`、`retrieve`、`learn`、`evolve` 等操作的额外输入规则 |
| `limitations`、`implementation_notes` | 方法限制和实现说明 |

`MethodCapabilities` 重点声明：

```text
modalities              支持的内容模态
forms                   记忆形式
operations              observe/retrieve/learn/evolve 等操作
integration_slots       方法输出可接入 Agent 的位置
accepted_events         可接收的事件类型
scopes                  支持的作用域类型
required_episode_fields 学习单元必须提供的字段
read_only_mode          native、snapshot 或 unsupported
supports_persistence    是否支持 save/load
max_scopes              可同时维护的作用域数量上限
```

运行时依据这些声明执行能力检查。声明了某项能力的方法必须提供对应的方法实现，Agent 或评测协议缺少必要条件时会在运行前被拦截。

### 3.4 注册、目录和执行器

| 对象 | 源码 | 职责 |
|---|---|---|
| `PluginRegistry` | `core/registry.py` | 注册插件、加载内置方法、发现 entry point、按 `method_id` 查找方法 |
| `MethodCatalog` | `catalog.py` | 把方法描述转换为面向用户的卡片 |
| `MethodExecutor` | `runtime/execution/base.py` | 定义方法运行边界和创建方式 |
| `InProcessExecutor` | 同上 | 在当前进程运行方法 |
| `SubprocessExecutor` | 同上及 `subprocess.py` | 在子进程运行方法，通过序列化协议转发调用 |
| `ServiceExecutor` | 同上及 `service.py` | 通过 HTTP 服务运行方法，并同步远程用量和存储信息 |

创建关系如下：

```text
MemAtlasConfig.method.method_id
        ↓
PluginRegistry.get(method_id)
        ↓
MethodPlugin + MethodDescriptor
        ↓
RuntimeConfig.executor
        ↓
MethodExecutor.create(...)
        ↓
BaseMemoryMethod 实例或远程代理
        ↓
Memory 统一调用 observe/retrieve/learn/evolve...
```

## 4. 配置与服务对象

### 4.1 `MemAtlasConfig`

源码：[core/config.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/core/config.py)。

MemAtlasConfig(

| 对象 | 作用 |
|---|---|
| `MethodConfig` | 选择方法并保存算法参数 |

`MemAtlasConfig` 支持从 JSON、TOML 或 YAML 加载，并在创建时完成配置结构和 Provider 解析。

### 4.2 `MethodServices` 与 `MethodContext`

`MethodServices` 是运行时注入给方法的服务集合：

```text
llm             方法内部使用的生成模型服务
embedder        向量服务
objects         方法所需的注入对象
source_roots    方法源码或外部仓库路径
artifact_dir    方法产物目录
usage           UsageLedger，用于模型和资源用量
provider_configs 解析后的 Provider 配置
resource_paths  方法注册的资源路径
```

`MethodContext` 在 `setup` 时传入：

```text
run_id          当前运行身份
method_config   方法参数
runtime_config  运行配置
metadata        运行元数据
```

Agent 使用的模型可以由 Agent 自己管理；`MethodServices.llm` 供记忆方法内部使用，两者在配置和职责上分开。

## 5. 核心数据结构

主要定义在 [core/models.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/core/models.py)、[core/scope.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/core/scope.py) 和 [core/episodes.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/core/episodes.py)。公共数据按用途收拢，方法特有字段放在 `extensions` 或方法清单规定的输入中。

### 5.1 基础类型

```python
Content = str | list[dict[str, Any]]
Scope = dict[str, str]
```

`Content` 可以是文本，或由带 `type` 和 `text`/`uri` 的内容块组成。`Scope` 使用 `user_id`、`agent_id`、`team_id`、`session_id`、`run_id` 中的字段表达记忆归属。框架将作用域规范化并生成稳定的 `scope_key`。

常用枚举：

| 类型 | 主要值 |
|---|---|
| `Modality` | `text`、`image`、`audio`、`video`、`artifact` |
| `EventKind` | `message`、`observation`、`action`、`tool_result`、`feedback`、`episode_start`、`episode_end`、`custom` |
| `Operation` | `observe`、`retrieve`、`learn`、`evolve`、`flush`、`reset`、`save`、`load`、`command` |

### 5.2 `MemoryEvent`：一次交互事件

```python
MemoryEvent(
    kind="message",
    content="Helios 的端口为 8443",
    role="assistant",
    event_id="...",       # 默认生成
    episode_id="...",     # 可选；关联一个学习单元
    timestamp="...",      # 默认生成 UTC 时间
    extensions={...},
    scope={...},           # 通常由 Memory 根据 config.scope 补齐
)
```

它可以表示用户消息、助手回复、工具输入、工具结果、环境观察或方法需要的自定义事件。`Memory.observe(event)` 会保存原始事件，并将事件交给方法的观察接口。事件的 `event_id` 用于去重和来源关联。

### 5.3 `MemoryContribution`：一次检索贡献

```python
MemoryContribution(
    items=[
        {
            "memory_id": "m1",
            "content": "Helios 的端口为 8443",
            "score": 0.9,
            "source_event_ids": ["e1"],
        }
    ],
    context=[
        {"content": "...", "source_item_indices": [0]}
    ],
    extensions={...},
)
```

| 字段 | 用途 |
|---|---|
| `items` | 记忆条目、身份、分数和来源事件 |
| `context` | 方法整理后供 Agent 使用的内容，可关联多个 `items` |
| `extensions` | 方法产生或要求的专有输出，例如策略、工具评价或直接答案 |

Agent 可以直接读取 `items` 或 `context`，也可以按照自己的提示格式组织内容。实际用于回答的贡献应放入 `MemoryEpisode.applied_memory`，以保留来源和方法关联信息。

### 5.4 `MemoryEpisode`：一个学习单元

```python
MemoryEpisode(
    episode_id="case-A",
    task="查询 Helios 的端口",
    events=[...],            # 可以省略，由已记录事件补齐
    output="Helios 的端口为 8443",
    success=True,
    reward=1.0,
    feedback="答案验证通过",
    applied_memory=[contribution],
    extensions={...},
    scope={...},
)
```

`MemoryEpisode` 是交给方法学习的一份完整数据。它的粒度由方法和实际任务决定，可以是一条资料、一轮对话、一个病例或一段完整 Agent 轨迹。`episode_id` 必须稳定且唯一；事件可以提前通过 `observe` 逐条记录，也可以在 `learn` 时一次性提供。若事件已记录，`learn` 可以只提供相同 `episode_id` 的任务结果、反馈和应用记忆。

`success`、`reward`、`feedback` 只在方法或评测协议要求时填写，必须使用真实业务反馈。方法特有数据放入 `extensions`，避免为单一方法扩展公共对象。

### 5.5 `EpisodeResult` 与 `BatchResult`

这两个对象记录评测或运行过程中的处理状态：

| 对象 | 关键内容 |
|---|---|
| `EpisodeResult` | `execution`、`feedback`、`learning`、`error`、`metadata`；分别表示执行、反馈和学习的状态 |
| `BatchResult` | 一批 `EpisodeResult`、批次指标和计数，用于训练进度与失败统计 |

`EpisodeResult` 的处理状态与 `MemoryEpisode` 的任务结果分开保存。一个失败的 Agent 任务仍可以形成有效的学习经历，是否从中形成记忆由方法决定。

### 5.6 `OperationTrace`

`OperationTrace` 记录一次方法操作的 `method_id`、操作名、开始时间、耗时、成功状态、输入输出规模、错误和运行元数据。`Memory.stats()` 和评测结果中的 traces 使用它进行操作级统计。

## 6. Memory 内部状态与公共边界

### 6.1 `EpisodeHistory`

源码：[runtime/history.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/runtime/history.py)。

`EpisodeHistory` 保存公共层需要的运行记录：

```text
events       事件身份 -> 序列化事件
observed     已交给方法 observe 的事件身份
episodes     学习单元身份 -> 学习单元及事件关联
results      学习单元身份 -> EpisodeResult
```

重要操作包括：

1. `add_event`：登记事件并检查身份冲突。
2. `episode_events`：按 `episode_id + scope` 找到已记录事件。
3. `record_episode`：保存学习单元和事件关联。
4. `record_result`：保存处理状态。
5. `mark_observed`：标记已调用方法 `observe` 的事件，避免重复处理。
6. `snapshot` / `restore`：保存和恢复公共历史。
7. `reset(scope)`：按作用域清理事件、学习单元和结果。

### 6.2 `MemoryContract`

源码：[runtime/contract.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/runtime/contract.py)。

`MemoryContract` 读取 `MethodDescriptor`，在运行边界检查：

```text
operation       是否声明支持该操作
scope           作用域字段和数量限制
event           事件类型和内容模态
episode         学习单元必需字段
read_only       冻结模式和保存/恢复能力
```

方法声明决定实际可用能力。公共入口保持统一，运行时会在方法不支持或输入不满足时给出能力错误。

### 6.3 `TraceCollector` 与 `UsageLedger`

源码：[core/telemetry.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/core/telemetry.py)。

`TraceCollector` 保存操作耗时和错误。`UsageLedger` 保存模型调用、Token、费用、阶段、运行、案例和资源信息，并可写入 `usage.jsonl`。记忆方法内部调用和 Agent/评测调用使用不同的 phase，评测结果可以据此汇总时间、Token、费用和进程资源。

### 6.4 保存、恢复和冻结

`Memory.save(path)` 保存：

```text
方法状态
公共事件、学习单元和 EpisodeResult
已使用的作用域
用量记录和定价信息
方法与配置签名、校验摘要
```

`Memory.load(path)` 会检查 schema、校验摘要、方法身份、配置签名、作用域和定价是否匹配，再恢复方法状态和公共历史。

`read_only()` 根据方法声明执行冻结：

1. `native`：依靠方法自身的只读能力。
2. `snapshot`：保存状态，测试结束后恢复。
3. `unsupported`：拒绝冻结评测。

冻结上下文允许检索和 Agent 执行。学习、演化、重置和其他持久记忆更新会被拒绝或回滚；冻结评测本身不决定是否调用 `evolve`。

## 7. 评测层关键对象

评测层位于 `evaluation/` 和 `benchmarks/`，负责把多个记忆回合组织成可复现的实验。它使用 `Memory` 公共接口，维护实验进度、评分、冻结检查点、恢复和资源统计。

### 7.1 Benchmark 数据和评分

源码：[core/evaluation.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/core/evaluation.py)、[benchmarks/base.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/benchmarks/base.py)。

```python
BenchmarkCase(
    case_id="case-A",
    query=...,
    scope={...},
    history=(...),
    reference=...,
    episode=...,
    metadata={...},
)
```

| 对象 | 作用 |
|---|---|
| `BenchmarkCase` | 一个评测案例，包含查询、历史、参考答案和可选学习经历 |
| `Prediction` | Agent 对案例的输出、参考答案、实际应用的记忆贡献和元数据 |
| `EvaluationResult` | 一个方法在一个 Benchmark 上的预测、指标、资源、失败和追踪 |
| `BenchmarkAdapter` | 提供案例、原生评分和 Benchmark 描述 |

Benchmark 负责数据和原生评分；通用评测器负责汇总预测、公共指标、资源和失败信息。

### 7.2 `ExperimentConfig` 与 `ExperimentRunner`

源码：[evaluation/experiment.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/evaluation/experiment.py)。

`ExperimentConfig` 描述一次方法比较实验：

```text
methods       待比较的 MemAtlasConfig 列表
benchmark     数据集类型和路径
protocol      streaming、experience_train_test 或 interactive_agent
split         测试数据划分
train_split   训练数据划分
metrics       评测指标
execution     批量覆盖执行器和超时等运行设置
output_dir    结果目录
```

`ExperimentRunner` 是评测入口，主要负责：

1. 读取实验配置并构造 Benchmark 和协议。
2. 对每个方法运行配置、服务和协议输入检查。
3. 调用 `MatrixRunner`，为每个方法创建独立 `Memory`。
4. 执行训练或历史导入，再逐案例运行 Agent/answerer。
5. 在冻结上下文中完成冻结评测，并验证持久状态没有变化。
6. 汇总 Benchmark 原生指标、通用指标、操作追踪、Token、费用和进程资源。
7. 写入可恢复的实验结果和报告。

### 7.3 评测协议

源码：[evaluation/protocols/memory.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/evaluation/protocols/memory.py)、[evaluation/protocols/agent.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/evaluation/protocols/agent.py)。

| 协议 | 作用 |
|---|---|
| `StreamingMemoryProtocol` | 按案例顺序使用查询和历史，组织连续记忆使用 |
| `ExperienceTrainTestProtocol` | 先用训练划分调用 `learn`，再在冻结状态中测试 |
| `AgentRunProtocol` | 调用外部 Agent；Agent 返回 `MemoryEpisode`，协议负责学习和评分 |

评测协议只负责组织案例、学习边界、冻结边界和预测结果。Agent 的具体执行逻辑由 `answerer` 或 `AgentRun` 回调提供。

### 7.4 `ExperiencePlan` 与 `ExperienceRunner`

源码：[evaluation/experience.py](/C:/Users/12084/Desktop/研究生/code/MemAtlas/src/mematlas/evaluation/experience.py)。

这是连续学习和 MemoryRSI 运行的实验调度层：

```text
ExperiencePlan
  ├─ 训练案例和测试案例
  ├─ 批次划分
  ├─ 检查点
  ├─ 失败策略
  └─ 快照策略
        ↓
ExperienceRunner
  ├─ 逐批调用训练回调
  ├─ 保存学习进度和实验曲线
  ├─ 在检查点进入 read_only() 执行冻结测试
  ├─ 保存 Memory 快照和用量账本
  └─ 支持从检查点恢复
```

`ExperienceRunner` 负责实验级的批次、进度、快照和恢复。某个方法何时完成原生批次、epoch 或独立演化，仍由该方法的接入规则和训练回调表达；实验检查点本身只负责调度和测量。

## 9. Agent 的基本使用流程

下面伪代码保留当前公共对象和方法名。Agent 自己完成模型调用，Memory 只接收真实事件、检索和学习数据。

```python
from uuid import uuid4

from mematlas import Memory, MemoryEvent, MemoryEpisode


async def run_one_case(agent_call, question, config):
    report = Memory.check(config)
    if not report["ready"]:
        raise RuntimeError(report)

    async with Memory(config) as memory:
        episode_id = uuid4().hex

        # 交互事件发生时记录；具体方法决定即时写入、缓冲或等待学习单元。
        await memory.observe(MemoryEvent(
            kind="message",
            role="user",
            content=question,
            episode_id=episode_id,
        ))

        contribution = await memory.retrieve(question, top_k=3)
        answer = await agent_call(question, contribution)

        await memory.observe(MemoryEvent(
            kind="message",
            role="assistant",
            content=answer,
            episode_id=episode_id,
        ))

        await memory.learn(MemoryEpisode(
            episode_id=episode_id,
            task=question,
            output=answer,
            applied_memory=[contribution],
            # success/reward/feedback 按方法清单和真实业务反馈填写。
        ))

        # 只有方法拥有独立演化机制，且达到其规定条件时才调用。
        # await memory.evolve()

        return answer
```

多个串行案例可以复用一个 `Memory`：每个案例使用新的 `episode_id`，长期记忆和方法状态继续积累。需要切换记忆方法时，优先保持 `observe`、`retrieve`、`learn` 的调用位置；方法要求额外字段或少量接入调整时，按照方法清单补充。

## 10. 评测主流程

```python
experiment = ExperimentConfig.from_dict({
    "methods": [config_a, config_b],
    "benchmark": {"kind": "locomo", "path": "data.json"},
    "protocol": "streaming_memory",
})

runner = ExperimentRunner()
reports = await runner.evaluate(experiment)
```

评测执行过程为：

```text
ExperimentConfig
    ↓
构造 BenchmarkAdapter 和 EvaluationProtocol
    ↓
逐个方法执行 check 和 protocol preflight
    ↓
为每个方法创建独立 Memory
    ↓
训练/导入历史（如协议要求）
    ↓
逐案例 retrieve，并运行 answerer 或 Agent
    ↓
记录 Prediction，必要时 learn
    ↓
冻结上下文执行测试，检查记忆状态未改变
    ↓
Benchmark 原生评分 + 通用指标 + 资源统计
    ↓
EvaluationResult 和实验报告
```

连续学习实验使用 `ExperiencePlan` 和 `ExperienceRunner`，以训练批次和明确检查点组织多个交互周期。`evolve` 是否发生由方法自身的演化机制、方法清单和训练回调决定。
