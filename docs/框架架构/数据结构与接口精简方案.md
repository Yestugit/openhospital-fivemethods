# 数据结构与接口精简方案

更新：2026-10-30。——10.30

状态：已审阅的修改方案，尚未实施。依据当前工作区源码，分支 `refactor/1011-framework-episodes`、HEAD `7fffbd1`，包含现有未提交改动。

## 0. 边界与原则

RiseMem 是研究工具箱。Agent 负责模型调用、工具执行、提示组装和业务决策；Memory 负责接收信息、提供记忆和更新记忆。同一含义使用一种主要数据结构，同一目的保留一个公共入口；共性接口保持精简，特殊能力按方法清单提供，不为假设中的适配场景增加抽象。

移除 `Memory.call_model()`、`call_tool()` 及提示注入功能，示例和场景代码直接调用已有 Agent。记忆方法内部用于提取、检索或维护记忆的模型调用继续保留。M2A 等方法的原生直接答案作为记忆输出返回，由 Agent 决定如何使用。

## 1. 数据结构：三种核心交互数据

当前主要转换链为 `AgentStep → MemoryEvent`、`AgentTrace → MemoryEpisode → EpisodeOutcome`；`MemoryApplication` 再次包装记忆输出，部分关键数据通过 `metadata` 隐含传递。

| 目标结构 | 表达什么 | 对现有结构的调整 |
|---|---|---|
| `MemoryEvent` | 一条消息、动作、工具结果或观察 | 合并 `AgentStep`；查询复用相同内容表达，移除独立的 `DecisionContext` |
| `MemoryEpisode` | 一次完整经历及真实结果 | 合并 `AgentTrace`，将 `EpisodeOutcome` 的结果字段直接纳入 |
| `MemoryContribution` | 方法提供给 Agent 的记忆输出 | 保留条目、可用内容及来源关系；移除 `MemoryApplication` 的再次包装 |

具体调整：

1. **事件统一。**保留 ID、归属、内容、类型和时间等必要字段，Agent、Benchmark 与方法接入共同使用。查询传给检索接口时不自动写入记忆，检索数量等选项通过参数传入。
2. **经历统一。**明确保存回合 ID、任务、完整事件、最终输出、真实反馈和实际使用的记忆来源。反馈晚到时，由调用方保存同一份经历，补齐后提交。
3. **关键字段明确。**实际应用来源、已观察事件 ID 和记忆决策使用明确字段；`metadata` 保存场景或方法补充信息。检索候选与实际应用分别记录，裁剪输出后保留准确来源，空检索的策略决策也能传回方法。
4. **减少辅助包装。**归属、内容块、记忆条目采用固定的嵌套字段格式，减少必须单独构造的对象。配置、内部统计和方法原生数据按职责保留；`EpisodeResult`、`BatchResult` 等尽量由内部处理。
5. **评测复用经历。**执行结果复用 `MemoryEpisode`，减少再转换为 `Prediction`。参考答案保留在评测侧，供评分使用。

主要修改：[core/models.py](../../core/models.py)、[core/trajectory.py](../../core/trajectory.py)、[core/evaluation.py](../../core/evaluation.py)，以及相应的序列化和方法输入映射。

## 2. 接口：一个目的一个入口

### 2.1 Memory 的主要操作

| 目的 | 建议保留 | 收拢内容 |
|---|---|---|
| 创建 Memory | `Memory(config)` | 移除 `from_dict`、`from_config`、`MemAtlas.memory` 等重复创建包装 |
| 接收单条信息 | `observe(event)` | 合并 `record` 与 `observe`，移除 `record_step` 的另一套表达 |
| 请求记忆 | `retrieve(event, ...)` | 合并 `recall` 与 `retrieve`，必要检索选项通过参数传入 |
| 提交完整经历 | `learn(episode)` | 收拢 `ingest_history`、`submit_episode`、`submit_feedback` 等学习路径 |
| 提交缓冲写入 | `flush()` | 对用户只保留一个入口，插件内部按原规则处理 |
| 保存／恢复 | `save(...)`／`load(...)` | 收拢公开状态保存与检查点包装，恢复时校验方法和配置 |
| 清理、冻结、统计 | `reset()`、`read_only()`、`stats()` | 分别保留独立职责 |
| 方法特有能力 | `command(name, payload)` | 沿用现有扩展入口，逐方法说明可调用命令与条件 |

普通整回合使用以 `retrieve()` 和 `learn()` 为主；需要在线观察的方法按要求调用 `observe()`。配置检查保留 `Memory.check()`，通过异步上下文管理初始化与关闭。

`learn(episode)` 接收完整经历，按方法规则衔接事件输入与经历学习，保留原生更新时机。已在线观察的事件通过稳定 ID 避免重复写入；提交的经历始终保留完整事件，供算法学习使用。缺少必要反馈时明确报错，不生成替代标签。

用户层与插件层的同一操作采用一致语义，内部调用和传输统一到一条实现路径。

### 2.2 移出 Memory 的 Agent 任务处理

移除 `start_episode()`、`finish_task()`、`discard_episode()` 等 Agent 任务管理入口，由调用方或评测协议维护同一个 `MemoryEpisode`：

```text
Agent／场景执行并记录实际过程
    → 形成 MemoryEpisode，取得真实反馈
    → memory.learn(episode)
```

Memory 保留接收、学习、去重和恢复所需记录；评测侧负责任务执行状态、待反馈经历与实验进度。复用现有通用处理代码，避免各场景重复实现，不新增通用 Agent 执行框架。

方法内部的任务状态继续保留，例如 MemCon 的任务上下文、MemRL／MemQ 的批次状态及 AEL 的维护状态。

### 2.3 评测与 Benchmark

1. **实验执行保留 `ExperimentRunner.evaluate()`。**问答、连续学习和恢复通过实验配置与必要参数选择，复用现有内部流程；收拢 `evaluate_qa()`、`evaluate_experience()`、`resume_experience()` 等公开包装。检查与读取结果分别保留 `check()`、`results()`。
2. **Benchmark 保留 `cases()` 和一个异步评分入口。**收拢 `native_score()`、`native_score_async()`，保留原生评分内容；同步计算可在异步评分方法内部直接完成。
3. **特殊更新按方法要求调用。**批次、epoch、分组维护等要求由方法声明和扩展接口承接，评测层按真实边界通知，避免不断增加公共方法或把保存当成学习边界。

方法和 Benchmark 的参数、可调用接口、必需步骤与条件清单，分别按[方法集成任务](../方法集成/项目任务与进展.md)和[测评任务](../测评/项目任务与进展.md)补齐。必要条件不满足时阻止相应运行。

## 3. 实施顺序与验收

| 顺序 | 主要位置 | 修改内容 |
|---|---|---|
| 1 | `core` | 确定三种核心结构、关键字段与旧结构映射 |
| 2 | `runtime`、`core/plugin.py`、方法适配与执行器 | 收拢 Memory 接口，统一输入输出和序列化，移出 Agent 调用功能 |
| 3 | `evaluation`、`benchmarks`、医院适配 | 复用统一经历，调整执行、反馈、评分、冻结与恢复路径 |
| 4 | 公共导出、示例、README、测试 | 删除重复入口，同步用法，分批提交 Git |

先完成数据与接口审定，再分步修改。重点验证普通 Agent 接入、历史导入、在线观察和整回合学习；覆盖 MemRL／MemQ 的批次或 epoch 更新、AEL 维护、M2A 图文输入与直接答案。

验收要求：原生算法与更新时机保留；观察与经历提交不重复写入；冻结测试不更新训练记忆；延迟反馈关联原经历；中断恢复后方法状态、执行／反馈／学习记录、来源和资源统计保持一致。
