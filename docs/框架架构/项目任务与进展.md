# 框架架构：项目任务与进展

更新：2026-11-01

当前源码基线：内层仓库分支 `refactor/rsi-evaluation`，提交 `7597c34`。

## 1. 改进目标

开源后让用户更容易接入 Memory 方法和运行测评。公共入口保持少而清楚，方法保留原生算法、存储和更新时机；框架围绕实际需求改进，不追求覆盖所有场景。

| 改进任务 | 目标 |
|---|---|
| 收拢公共接口 | 同一目的保留一个主要入口；公共调用有固定用途，切换方法时尽量沿用原调用位置 |
| 精简公共数据 | 同一含义尽量使用一种表达；方法特有数据按需保留 |
| 理顺执行流程 | 明确通用层、场景层、实验层职责，复用公共回合处理，保留方法原生更新机制 |
| 补齐使用清单与检查 | 方法和 Benchmark 说明必要参数、数据、步骤和条件；缺少条件时明确报错 |
| 同步文档、示例与验证 | 代码调整后同步用户说明和示例，验证典型流程，分批提交 Git |

## 2. 当前使用入口

Agent 使用 `Memory`：通过 `observe(event)` 上报交互事件，按需调用 `retrieve(query)`，在学习单元完成时调用 `learn(episode)`。方法可以采用不同内部处理，用户按方法要求补充必要数据或作少量接入调整。

`evolve` 仅供需要 Agent 主动触发演化的方法使用；可自行判断演化时机的方法由内部处理。`flush` 只在方法要求提交缓冲工作时调用，不是每次 `observe` 后的统一步骤。

测评使用 `ExperimentConfig` 和 `ExperimentRunner`，公开操作为 `check(config)`、`evaluate(config)`、`results(path)`。三种安排为：

| protocol | 用途 |
|---|---|
| `streaming_memory` | 给定历史，逐题检索并回答 |
| `experience_train_test` | 提交训练经历后冻结测试 |
| `experience_learning_curve` | 连续训练并在检查点测试 |

连续学习调度由内部 `_ExperienceRunner` 处理。OpenHospital 通过 `benchmark.kind="openhospital"` 接入，要求单个 Memory 方法和 `experience_learning_curve`；`OpenHospitalServices` 管理本地服务。

## 3. 当前进度

| 项目 | 当前状态 |
|---|---|
| Memory 公共运行时 | 已提供统一配置检查、事件输入、检索、学习、只读、保存恢复和运行统计 |
| 普通 Benchmark | 已统一到 `ExperimentConfig / ExperimentRunner`，内置 QA 与用户 Agent 共用测评入口 |
| OpenHospital RSI | 已接入统一测评入口、医院场景适配、服务管理、病例计划、检查点与恢复路径 |
| 方法迁移 | Mem0、MemRL、MemoryOS 声明 Memory v2；其余 11 个具名方法和 4 个控制基线待迁移 |
| 三层职责 | 主要入口已按通用层、场景层、实验层组织；医院执行仍处理部分训练批次和反馈边界，职责尚未完全收拢 |
| 使用说明与条件检查 | 公共接口及部分方法、Benchmark 说明和检查已具备；逐方法清单与完整检查覆盖仍待补齐 |

三层职责按当前代码理解：

```text
通用层：Memory 操作、公共经历记录、反馈、冻结与恢复
场景层：Agent 与环境交互、场景数据和反馈映射
实验层：实验配置、案例调度、检查点评测和结果汇总
```

RSI 文档提出的 `40×5` 是参考方案；当前 OpenHospital 代码默认仍为 `50×5`，参考方案不代表已运行的正式实验。

## 4. 后续任务

1. 将其余 11 个方法和 4 个控制基线迁移到 Memory v2，并完成对应使用清单。
2. 补齐方法、Benchmark 和 OpenHospital 的必要条件检查与用户说明。
3. 按实际调用链继续收拢通用回合能力，明确场景和实验层的边界。
4. 验证普通 Benchmark、连续学习、冻结测试、反馈和恢复等典型流程，并同步示例与 README。

具体设计原则见[框架重新设计](框架重新设计.md)，近期代码与实验记录见[实验日志](实验日志.md)。
