**1. 基本流程：用户如何使用，框架内部如何执行**

RiseMem 的整体关系如下：

```text
Agent 开发者
│
├─ 自己的 Agent
│    └─ 提示组装、模型调用、工具执行、任务评价
│
└─ Memory
     ├─ 公共层：检查输入、记录事件、组织经历、管理状态
     │
     └─ 具体记忆方法：提取、存储、检索、更新和演化记忆
```

你可以先用“一份记忆连续处理多个问题”理解主流程：

```text
创建 Memory
    │
    ├─ 问题 A：检索 → Agent 执行 → 提交经历学习
    │
    ├─ 问题 B：检索已有经验 → Agent 执行 → 提交经历学习
    │
    ├─ 按方法要求进行记忆演化
    │
    └─ 保存并关闭
```

下面是接入流程示意，方法 ID 和参数需要按所选方法填写：

```python
from uuid import uuid4
from mematlas import Memory, MemoryEvent, MemoryEpisode

config = {
    "method": {
        "method_id": "已迁移的方法ID",
        "params": {},                       # 方法自己的算法参数
    },
    "scope": {
        "user_id": "alice",
        "agent_id": "assistant",
    },
    "runtime": {
        "artifact_dir": ".mematlas/my-agent",
    },
    # 方法需要模型时，在 providers 中配置。
}

report = Memory.check(config)
if not report["ready"]:
    raise RuntimeError(report)

async with Memory(config) as memory:
    for question in questions:
        # ① 检索记忆
        contribution = await memory.retrieve(question, top_k=3)

        # ② Agent 自己组织提示、调用模型与工具
        # 此处约定 Agent 使用了传入的全部 contribution。
        answer = await my_agent(question, contribution)

        # ③ 提供真实交互过程，提交学习
        episode = MemoryEpisode(
            episode_id=uuid4().hex,
            task=question,
            events=[
                MemoryEvent(
                    kind="message", role="user", content=question,
                ),
                MemoryEvent(
                    kind="message", role="assistant", content=answer,
                ),
            ],
            output=answer,
            applied_memory=[contribution],
        )
        await memory.learn(episode)

    # 方法支持且要求独立演化时，再调用 memory.evolve()。
    await memory.save("memory.json")
```

这段代码中，`Memory` 在循环外创建，因此多个问题能够使用此前积累的长期记忆。每份学习数据使用独立的 `episode_id`。

进入框架内部，一次操作大致经过这条链：

```text
memory.retrieve(...) / memory.learn(...)
    │
    ▼
Memory 公共层
检查方法是否支持、输入是否满足要求、当前是否允许更新
    │
    ▼
执行器
在当前进程、子进程或 HTTP 服务中调用方法
    │
    ▼
具体记忆方法
执行自己的检索或学习算法，访问自己的存储与模型服务
    │
    ▼
Memory 公共层
返回结果，记录操作状态与资源用量
```

其中最容易混淆的是四个核心操作：

| 操作 | 交给它什么 | 负责什么 |
|---|---|---|
| `observe(event)` | 一条消息、动作、工具结果或资料 | 公共层记录事件，方法按自己的规则处理 |
| `retrieve(query)` | 当前查询 | 返回可以提供给 Agent 的记忆贡献 |
| `learn(episode)` | 一份明确的学习数据 | 方法吸收该学习单元，形成或更新记忆 |
| `evolve()` | 方法要求的演化参数 | 对积累的记忆或经历进行归纳、整合、筛选或策略改进 |

**每个方法声明自己支持哪些操作，用户只调用该方法需要的部分。**

输入学习数据有两种常见方式：

```text
已有完整数据：
MemoryEpisode(events=[...]) → learn()

需要逐步记录：
observe(event，带 episode_id) 多次
    → learn(MemoryEpisode，沿用 episode_id，省略 events)
    → 公共层补齐已记录的事件
```

这里有几个必须掌握的边界：

1. `observe()` 是否立即写入长期记忆，由具体方法决定。公共层允许方法即时写入、缓冲或等待完整经历。
2. `learn()` 始终向方法提供完整学习数据，并告知哪些事件已经经过方法侧 `observe()`。方法结合自己的已写入与缓冲状态避免重复处理。
3. `MemoryEpisode` 可以是一条资料、一轮对话或完整任务经历，粒度取决于方法。
4. `flush()` 用于处理方法的待办缓冲。Agent 无需每次操作后调用；公共评测、冻结准备和关闭运行可以在必要节点调用。
5. `save()` 保存当前状态，包括方法需要保留的待处理状态；它不额外触发演化。

冻结使用已有记忆时：

```python
async with memory.read_only():
    contribution = await memory.retrieve(question)
    answer = await my_agent(question, contribution)
```

冻结期间 Agent 可以正常执行，轨迹由调用方保留；Memory 禁止学习、演化和其他更新。恢复则在新建 Memory 后显式调用：

```python
await memory.load("memory.json")
```

**2. 重要对象、方法和数据：开发时需要认识谁**

先区分四个主要对象：

| 对象 | 职责 | 谁通常需要接触 |
|---|---|---|
| `Memory` | 对用户提供统一接口，管理检查、历史、冻结、保存恢复和操作状态 | Agent 开发者 |
| `BaseMemoryMethod` | 约定具体记忆方法如何实现观察、检索、学习等操作 | 方法集成开发者 |
| `MethodPlugin` | 描述方法、检查参数、创建方法实例 | 方法集成开发者 |
| `ExperimentRunner` | 组织多个方法或多个训练评测回合 | 实验开发者 |

它们之间的关系：

```text
方法注册表 PluginRegistry
    │
    └─ MethodPlugin
         ├─ descriptor：方法能力、参数、依赖与使用条件
         └─ create_method()：创建具体方法对象
                                  │
                                  ▼
                         BaseMemoryMethod 的实现
                                  ▲
                                  │
                               Memory
                                  ▲
                                  │
                       Agent 或 ExperimentRunner
```

例如，未来迁移后的 Mem0 接入应当具有这样的结构：

```python
class Mem0Memory(BaseMemoryMethod):
    async def observe(self, event):
        # 按 Mem0 的规则接收和处理信息
        ...

    async def retrieve(self, query, *, top_k, scope, extensions):
        # 调用 Mem0 自己的检索算法
        return MemoryContribution(...)

    async def learn(self, episode, *, observed_event_ids):
        # 接收完整学习数据，避免重复写入
        ...

    async def save(self):
        # 返回方法自身的可恢复状态
        ...

    async def load(self, state):
        # 恢复方法自身状态
        ...


class Mem0Plugin(MethodPlugin):
    descriptor = ...  # 支持的操作、参数、依赖、限制等

    def create_method(self, config, services):
        return Mem0Memory(config, services)
```

方法保留自己的算法实现。公共层主要统一调用方式和必要规则。

公共交互数据重点掌握三个：

| 数据 | 表示什么 | 关键内容 |
|---|---|---|
| `MemoryEvent` | 一条实际发生的信息 | `kind`、`content`、`role`、`event_id`、可选 `episode_id` |
| `MemoryEpisode` | 一份提交学习的数据 | `episode_id`、`events`、可选任务、输出、反馈和实际使用的记忆 |
| `MemoryContribution` | 一次检索返回的记忆贡献 | `items`、可选整理内容 `context`、方法专有数据 `extensions` |

对应关系如下：

```text
真实交互
    │
    └─ 多条 MemoryEvent
              │
              ▼
        MemoryEpisode ──learn()──► 记忆方法
              ▲                       │
              │                       │ retrieve()
              │                       ▼
              └─ applied_memory ◄─ MemoryContribution
                   记录实际用过的贡献
```

`MemoryContribution` 中：

```python
contribution.items       # 记忆条目
contribution.context     # 方法整理后的上下文，可为空
contribution.extensions  # 方法专有输出，可为空
```

普通记忆条目类似：

```python
{
    "memory_id": "m1",
    "content": "Helios 的端口为 8443",
    "score": 0.9,
    "source_event_ids": ["e1"],
}
```

**`applied_memory` 保存实际提供给 Agent 的完整贡献。**如果 Agent 只使用一部分检索结果，应记录实际使用的部分及其关联信息。

还有两种标识需要分清：

| 标识 | 用途 | 例子 |
|---|---|---|
| `scope` | 确定记忆归属 | 用户 Alice 的助手记忆 |
| `episode_id` | 区分学习单元 | 病例 A、病例 B、某轮对话 |

默认 `scope` 放在配置中；调用确需切换且方法支持时，可以覆盖。同一份归属下可以积累多个学习单元。

开发公共层时，还需要认识以下辅助对象：

1. **`EpisodeHistory`**：保存原始事件、经历关联及学习处理状态。事件正文保存一份，经历通过引用组织事件。
2. **`MethodServices`**：向具体方法提供 LLM、Embedding、存储产物目录和用量记录。这里的模型用于记忆算法自身。
3. **执行器**：决定具体方法在哪里运行，统一承接相同的方法协议。
4. **`EpisodeResult`**：记录执行、反馈和学习分别处于什么状态。它用于进度与恢复，业务成功与“已经提交学习”分别记录。

评测再增加一条关系：

```text
ExperimentRunner
    ├─ Benchmark：提供案例和原生评分
    ├─ 评测协议：决定如何输入历史、执行 Agent、训练与冻结
    └─ Memory：执行实际记忆操作
```

连续学习通过 `ExperiencePlan` 指定训练安排和检查点，由公共实验调度执行多个回合。

**3. 文件架构：每个目录负责什么，要改功能去哪里找**

现有源码可以按下面这棵树阅读：

```text
src/mematlas/
│
├─ __init__.py             对外导出主要对象
├─ api.py                  MemAtlas：查询方法目录与方法说明
├─ catalog.py              整理面向使用者的方法信息
├─ selection.py            需求解析、方法推荐、配置生成
│
├─ core/                   公共数据、方法协议和基础规则
│
├─ runtime/                Memory 的运行实现
│   └─ execution/          进程内、子进程、HTTP 执行
│
├─ methods/                具体记忆方法与方法内部共用工具
│   ├─ mem0/
│   ├─ memrl/
│   ├─ reasoningbank/
│   └─ ...
│
├─ providers/              LLM、Embedding 服务与调用用量采集
│
├─ evaluation/             公共评测、连续学习调度与结果记录
│   ├─ protocols/          评测流程
│   ├─ metrics/            通用指标
│   └─ reporting/          结果输出
│
├─ benchmarks/             具体数据集接入与原生评分
│
├─ integrations/
│   └─ openhospital/       医生 Agent 与医院环境的场景适配
│
├─ cli/                    命令行入口
└─ docs/                   任务、设计与使用文档
```

最重要的目录职责如下：

| 目录 | 负责什么 | 修改示例 |
|---|---|---|
| `core/` | 大家共同使用的数据与约定 | 调整经历字段、方法能力声明、输入检查规则 |
| `runtime/` | 公共接口怎样执行 | 修改 `learn()` 的数据组装、冻结保护或恢复行为 |
| `methods/` | 每个方法的算法与接入 | 迁移 Mem0、修改某方法的检索或更新逻辑 |
| `providers/` | 记忆算法调用外部模型的服务 | 接入 Embedding 服务、采集模型用量 |
| `evaluation/` | 组织和评估多个回合 | 修改训练检查点、反馈调度、实验进度或汇总 |
| `benchmarks/` | 数据集解析和原生评分 | 接入新 Benchmark、修正数据读取与评分 |
| `integrations/` | Agent 与具体环境的映射 | 将医院交互转换为公共事件和学习数据 |

公共层最值得先读的文件只有这些：

| 文件 | 看懂什么 |
|---|---|
| `core/models.py` | 事件、学习单元和检索输出 |
| `core/config.py` | Memory 配置 |
| `core/plugin.py` | 具体方法需要遵循的协议，以及服务注入 |
| `core/capabilities.py` | 方法如何声明能力和使用条件 |
| `core/registry.py` | 方法如何被发现和创建 |
| `runtime/memory.py` | 所有公共操作的主要调用链 |
| `runtime/history.py` | 事件、经历、去重与处理状态如何保存 |
| `evaluation/experiment.py` | 实验统一入口 |
| `evaluation/protocols/` | 普通检索评测、Agent 评测和训练测试流程 |
| `evaluation/experience.py` | 连续学习、检查点与恢复调度 |

具体方法目录通常是：

```text
methods/某方法/
├─ method.yaml       方法说明：参数、能力、依赖、限制
├─ method.py         接入公共接口，转换必要的数据
├─ core.py           方法算法和存储实现
└─ 其他算法文件      按方法实际需要组织
```

**参与开发时，先判断修改属于哪一层：**

1. 所有方法共同需要遵守的行为，查看 `core/` 或 `runtime/`。
2. 某个方法独有的行为，留在对应 `methods/` 目录。
3. 多个回合如何训练、测试和计数，查看 `evaluation/`。
4. 数据集与评分，查看 `benchmarks/`；医生与医院服务映射，查看 `integrations/openhospital/`。

建议第一次实际阅读只走这一条路线：

```text
examples/end_to_end.py
    → core/models.py
    → runtime/memory.py 的 retrieve() 和 learn()
    → core/plugin.py
    → 一个具体方法的 method.py、method.yaml、core.py
```

当前可以先运行教学示例：

```powershell
.venv/Scripts/python.exe examples/end_to_end.py
```

它展示事件输入、经历学习、外部 Agent、演化、保存恢复，以及连续学习检查点。随后阅读 Mem0 时，要记住它仍待迁移：**公共层代表本轮目标协议，Mem0 的旧接入代码正是后续需要调整的部分。**
