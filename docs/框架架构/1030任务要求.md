项目与本次改进目标
RiseMem 是面向 MemoryRSI 的记忆方法集成与测评工具箱：接入不同记忆方法，让用户能够用于自己的 Agent，并开展方法比较和连续学习研究。各方法保留自己的算法、数据库与原生更新流程。
本次改进基于现有源码，重点解决此前不断迭代、考虑过多适配场景而产生的接口过多、数据结构相近、重复包装与转换、Agent 和 Memory 职责混杂。目标是让用户清楚需要配置什么、提供什么数据、调用哪些方法，框架内部也使用清晰一致的表达。
尝试改进框架代码，开源后，让用户使用我们这套框架的时候，能更容易使用。

用户已经明确的设计要求
1. **Agent 与 Memory 解耦。**Memory 不承担 Agent 的提示组装、模型调用、工具执行和业务决策。Agent 自行执行，通过清楚的接口使用记忆、提供真实经历与反馈。记忆算法自身需要的模型调用继续保留。
2. **同一目的只保留一个公共方法。**不能为不同适配场景提供多套功能相近的入口，也不同时保留快捷版、完整版和多种便利包装。不同职责可以分别保留，方法特有能力可以提供自己的接口。
3. **按用途精简公共数据结构。**同一含义尽量使用一种表达，合并相近对象，减少重复字段和来回转换，删除不必要的结构。**不预设总数，也不能仅为减少类数量，把复杂度搬进字典。**稳定信息优先放配置，简单信息可直接作为参数；确需独立传递的数据才保留相应结构。
4. **公共接口的用途和使用约定保持一致。**`observe` 用于上报需要写入记忆的交互事件，`retrieve` 用于按需获取记忆，`learn` 用于提交一个完成的学习单元。有独立演化机制的方法，evolve按需书写，不一定都有，按其规定的周期或条件调用 `evolve`，对一段时间内积累的记忆、经验或策略进行阶段性演化。各方法负责在内部实现这套使用约定。——10.31
5. **方法内部处理可以不同。**例如 Mem0 可以在收到助手回复后立即写入；MemRL 可以先记录事件，等 learn(episode) 收到完整轨迹和真实反馈后再更新。两种方法的内部机制可以不同，Agent 仍按同一个位置调用 observe 和 learn。方法负责处理即时写入、缓冲、去重或批次更新。
6. **切换方法时，尽量保留 Agent 原有流程。**方法可能需要不同的数据字段、反馈或事件类型，用户按清单补充即可；确实有必要时，可以增加少量调用或做小幅调整。目标是原有接入经过少量适配或无需适配，就能使用新方法。
6. **每个 Memory 方法和 Benchmark 提供简洁的使用清单。**说明参数、输入输出、必要数据与反馈、服务条件及原生处理规则；注明公共接口的固定用途，并说明方法所需的数据补充或少量接入调整。必要条件不满足时阻止运行，明确缺失项；只检查实际使用路径需要的条件。——10.31
   每个 Memory 方法通过 `__init__.py` 导出用户对象并简述使用条件，配置类、按需提供的专有输入类型与必要特有函数供 IDE 和 `help()` 查看，`example.py` 展示最小接入流程；`method.yaml` 保留程序声明与校验。具体编写按[方法书写约束](../方法集成/1031方法书写约束.md)执行，替换原 `usage.yaml` 和方法 README 形式。——10.31
7. **保持工具箱的复杂度边界。**做好真实需要的主要流程，不为各种假设场景设计通用机制。特殊适配允许用户自行补充，避免因此增加大量公共接口、配置和结构。
8. **同时照顾 Agent 接入和评测。**共享接口与数据调整时，同步迁移普通 Benchmark 和 OPH。评测专用的评分、进度、反馈、冻结和恢复数据按实际用途保留，减少普通 Agent 用户需要接触的内容。

9. **特有接口只用于必要的核心操作。**优先通过现有公共接口和方法所需的数据表达差异。只有现有接口无法承载方法的核心操作时，才增加少量特有接口，并说明原因。特有接口用于完成方法机制所需的操作，不用于增加附加功能。——10.31
