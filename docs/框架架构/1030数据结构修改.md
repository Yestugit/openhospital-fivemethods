
按这个思路，**先确定信息应该放在哪里，再决定是否需要独立的数据结构。稳定信息放配置，简单输入直接传参数，过程和经历使用统一结构，方法特殊需求留在扩展中。**

我建议采用下面这版设计。

**1. 数据怎样组织**

| 数据用途 | 改进后的设计 |
|---|---|
| 方法、模型服务、存储、默认记忆归属 | **放在 `config` 中**，创建 Memory 时确定，普通调用不重复填写 |
| 检索查询 | **直接传给 `retrieve()`**，查询、数量和必要上下文作为参数，不再要求构造 `DecisionContext` |
| 一条消息、动作或观察 | **统一为 `MemoryEvent`**，作为事件记录和经历中的基本单位 |
| 一次完整经历 | **统一为 `MemoryEpisode`**，包含任务、事件、最终输出与真实反馈 |
| 一次检索输出 | **统一为 `MemoryContribution`**，保存返回内容、来源及方法扩展，Agent 直接使用 |
| 方法特有数据 | **放在对应的扩展字段中**，复杂时由方法定义专用结构，公共层不增加特殊字段 |

这里的配置、事件、经历、检索输出各有用途；查询等信息通过参数表达，减少额外包装。

**2. 原有结构具体怎样调整**

| 原有结构 | 处理 |
|---|---|
| `MemoryScope` | 归属信息移到配置，取消用户必须构造的公共对象；现有 Benchmark 需要切换归属时按任务覆盖 |
| `DecisionContext` | 删除公共包装，必要信息改为检索参数 |
| `AgentStep`、`MemoryEvent` | 合并为 `MemoryEvent` |
| `AgentTrace`、`MemoryEpisode`、`EpisodeOutcome` | 合并为 `MemoryEpisode`，消除重复的结果、归属和扩展字段 |
| `ContentBlock` | 简化为事件、查询、记忆共用的固定内容格式；文本直接使用字符串，图文按约定提供，无需逐项构造内容对象 |
| `MemoryItem` | 简化为检索输出中的固定条目格式，保留必要的 ID、内容、得分和来源 |
| `MemoryContribution`、`MemoryApplication` | 保留前者并精简，删除应用包装；提示组装由 Agent 完成 |
| `ToolSpec`、`ModelHookSpec`、`ArtifactRef` | 移出公共核心，实际需要的方法自行提供 |

**3. 两个主要结构保留什么**

```text
MemoryEvent
├─ 事件 ID、时间
├─ 类型、角色、内容
└─ 扩展数据

MemoryEpisode
├─ 经历 ID、任务
├─ events：实际发生的事件
├─ output：最终输出
├─ success / reward / feedback：真实反馈，按需提供
├─ applied_memory：实际使用的记忆及来源
└─ extensions：方法专有数据
```

归属默认从配置取得，保存经历时记录实际归属，保证恢复和延迟反馈仍能正确关联。已经在线观察的事件继续保留在完整经历中，由框架避免重复处理。

检索输出保留**条目及来源、按需整理后的内容、方法扩展**。普通方法不重复保存相同文本；AWM、ExpeL 等方法确有整体格式化内容时才提供。框架产生的策略记录自动关联，减少用户手工传递。

**4. 改后用户怎样使用**

```python
async with Memory(config) as memory:
    contribution = await memory.retrieve(question, top_k=3)

    # 自己的 Agent 使用记忆、执行任务并记录事件。
    ...

    await memory.learn(episode)
```

需要在线观察的方法再调用 `observe(event)`。这些是拟调整的 API。

评测侧保留任务输入和实验汇总，执行过程复用事件与经历，减少 `AgentTrace → MemoryEpisode → Prediction` 的层层转换。内部状态、去重和资源记录继续由框架维护。

**这版精简同时处理类、字段和数据流：减少用户需要构造的对象，减少重复存放和转换，保留真实方法需要的信息。**


---



修改后，**配置统一保存稳定信息，记忆交互使用事件、完整经历、检索输出三种结构。**具体如下，均为设计方案。





```text
config（配置）
├─ method              方法及参数
├─ providers           记忆方法所需的模型服务
├─ runtime             存储、执行等配置
└─ scope               默认记忆归属

MemoryEvent（一条事件）
├─ event_id            事件标识
├─ timestamp           发生时间
├─ kind                消息、动作、观察、工具结果等
├─ role                参与角色
├─ content             文本或约定的图文内容
└─ extensions          场景或方法补充数据

MemoryEpisode（一次完整经历）
├─ episode_id          经历标识
├─ task                任务描述
├─ events              MemoryEvent 列表
├─ output              最终输出
├─ success             真实成功标签，可选
├─ reward              真实奖励，可选
├─ feedback            真实文字反馈，可选
├─ applied_memory      实际使用的记忆及来源
└─ extensions          场景或方法补充数据

MemoryContribution（一次检索输出）
├─ items               记忆条目：ID、内容、得分、来源
├─ context             方法整理后的内容及来源关联，按需提供
└─ extensions          方法特有输出与关联信息
```

有几个明确约定：

1. **查询直接传参数**，不再构造查询对象：`memory.retrieve(query, top_k=...)`。
2. **scope 默认来自 config**；确需按任务改变时覆盖，保存时由框架记录实际归属。
3. **内容、记忆条目采用固定嵌套格式**，不再额外要求构造 `ContentBlock`、`MemoryItem`。
4. **方法特殊数据进入扩展部分**，由对应方法声明和检查；框架产生的关联信息自动保留。

评测额外使用 `BenchmarkCase` 表达任务与参考答案、`EvaluationResult` 表达实验汇总，执行过程直接复用上述事件和经历。

原来的 `AgentStep`、`AgentTrace`、`EpisodeOutcome` 等合并进对应结构；`DecisionContext`、`MemoryApplication` 等包装移除。
