# 五方法效率执行器验收记录

本记录对应 `codex/openhospital-memory-methods`，基线 `main@50f3920`。正式 500 次诊疗尚未启动。真实小样本与历史实验、正式实验独立，不能据此比较五方法的最终性能。

## 实现范围

- `scripts/openhospital-memory-efficiency.py` 提供 check、smoke、run、resume、status、watch、stop、report；公共 ExperimentRunner 执行医院任务，五方法按 MemOS → Mem0 → MemMachine → EMem → Memora 串行。
- 一套实验持有 OS 排他锁；方法使用独立 scope、原生数据库、world、后台 worker、日志及检查点。独占 embedding 服务与便携 Neo4j 的数据目录位于试跑目录，不删除模型目录。
- 每轮记录记忆前台／后台活动区间并集、前台等待、后台活动、持久化、测量和总流程耗时；完整事件与心跳跨进程持久化。未闭合事件明确标记覆盖不完整及未知尾段。
- 新增经历按已接收事件身份计数；另记规范化完整载荷与失败／重试提交载荷。固定本地 tokenizer，全量枚举原生正文；Neo4j 外部数据库、事务日志和内存状态分别计量。
- 暂时性请求失败最多 8 次，耗尽进入可恢复暂停；保留子进程异常原因链。检查名兼容等价格式，检查 JSON 支持原请求后 3 次修复及合法目录兜底，不伪造患者信息或检查结果。
- 以完整病例为恢复边界；已保存诊疗只补评分、反思或学习，恢复已提交原生快照，不重放对话构建记忆。独立英文控制台每 5 秒输出进度。

初次结果：**208 passed，8 skipped**，日志 `.mematlas/efficiency-final-regression.log`；补充恢复／分组异常测试后为 **211 passed，8 skipped**，最终综合回归 **213 passed，8 skipped**，日志 `.mematlas/efficiency-final-regression-v4.log`。最终追加请求归因／Retry-After 的针对性复核为 31 passed。跳过项须查看测试 skip 原因，不当作通过。

另在各原生环境执行 MemOS 7 项（真实 Neo4j）、Mem0 19 项、MemMachine 7 项、EMem 21 项、Memora 7 项的既有验证，并补充全库只读检查器测试；具体环境、固定源码及原生验收边界见 `docs/方法集成/20261105_五方法native适配验收.md`。

受控覆盖包括前后台重叠与嵌套不重复计时、跨轮／跨 segment 汇总、硬中断尾段、排他锁、两种实验规模和名单隔离、事件身份去重与恢复、429／5xx／永久错误、8 次 embedding 请求预算、Retry-After、真实 subprocess 异常传递、检查 JSON 合法部分保留、医院响应丢失后的幂等缓存和恢复配置身份。

本地 Qwen embedding 接口每次最多 32 条。真实试跑发现 Mem0 原生逻辑批次可超过该值，传输桥分成至多 32 条的 HTTP 请求并保持顺序和原生向量规则；80 条受控输入验证为 32／32／16，三次实际调用分别计量。

## 真实小样本记录

受验套件：`.mematlas/efficiency-smoke-20261106-verified`，两例为 `Patient_00948`、`Patient_00278`，每方法 2×1，seed=0。使用本地 CPU embedding、1024 维、`qwen3.5-flash`；具体模型 URL、源码哈希、配置及名单哈希保存在 `suite.json`。密钥只在被忽略的 `.env.local` 中，不写入报告。

每方法首例正常暂停后恢复；Mem0 首例先发生超批量请求故障，诊疗已保存，修正传输层后仅补学习，再通过 stop／resume 验证完整病例边界。该次兼容变更逐文件审核并保存在 `reviewed-provider-compatibility.json`，未增加通用签名绕过开关；Mem0 正常暂停证据为 `mem0/manual-pause-verification.json`。

Mem0 第二例学习另暴露 CPU 默认 GQA 注意力路径的内存峰值：一次分配约 2.1 GiB 失败，8 次请求预算及恢复队列均实际触发。改用等价 fused SDPA：CPU flash 内核／CUDA efficient 内核，展开分组 KV，完整输入不截断。真实模型短文本对照余弦相似度 0.99999994、最大绝对误差 1.38e-7；8,802 token 长文本生成完整 1024 维向量，证据为 `.mematlas/embedding-cpu-fused-validation.json`。独立 CPU 单元测试覆盖分组 head、因果与显式 mask、scale 和 math 路径数值对照。

这次工程修正改变服务实现身份。为保留已落盘临床结果，在本次小样本中人工审核两项 embedding 身份差异，仅更新恢复契约与 plan signature 元数据并重算校验；原始 metadata 完整备份，原生状态／已存向量不改，记录见 `reviewed-cpu-attention-compatibility.json` 和 `reviewed-cpu-attention-originals/`。这是明确记录的试跑修复，不是自动检查点迁移；正常 resume 仍严格拒绝未审核的源码或环境变化。**此套中断且发生实现修正的计时只作工程验收证据，不能用于五方法效率排名。正式实验从空目录统一使用修正后的实现。**

MemMachine 首次 setup 在省略 `storage_path` 时失败，已改为当前独立 runtime workspace 下的默认目录；增加两次实例路径隔离与零模型 setup 验证。随后真实后台暴露官方语义提示输出列表与原生 `_SemanticFeatureUpdateRes` 对象封套之间的不一致，适配桥仅对通过该原生 Pydantic 校验的列表／单命令补 `commands` 封套，保留原始响应与转换审计。原生测试共 **9 项通过**，覆盖空列表、单命令、命令列表、已有封套及非法命令拒绝，不修改官方抽取提示和算法。

补全 `ExceptionGroup` 全部内部原因和实际 subprocess stderr 后，故障可追溯到原生验证错误；同时修正更早失败 attempt 无快照时的请求账本汇入、自动恢复退避／恢复加载计时、首次 setup 失败后的 smoke 正常暂停，以及医生／医院请求的 Retry-After 和逐请求标识、耗时。对应试跑人工兼容审核、原始契约／world 元数据备份见 `reviewed-background-diagnostics-*` 和 `reviewed-memmachine-envelope-*`；原生数据库和临床 bundle 保持原内容。历史已结束轮次不会被追溯伪造为采用新计量实现。

开发调试另有 `.mematlas/efficiency-smoke-20261106` 的 MemOS 首例诊疗：恢复时暴露 response journal 路径随 attempt 改变的问题，已改为方法稳定路径。该目录及额外一次真实诊疗成本完整保留，不混入受验套件的十例结果，不宣称本轮只发生十次实际诊疗。

MemMachine 真实响应还出现 delete 命令缺少原生 schema 必填 `value`。桥接层在原生结构验证失败时最多发出 3 次额外格式修复请求，携带原响应／schema／错误，不填默认事实或静默丢弃命令；耗尽仍暂停。每次响应和用量保留，审计写入 activity。原生 9 项测试增加修复成功及严格四次预算断言后通过，日志 `.mematlas/memmachine-efficiency-final-native.log`。

Memora 真实接入发现当前 Qwen endpoint 对结构化格式有两种兼容要求：消息中明确含 JSON，且仅提供 `response_format` 并不保证响应符合 schema。桥接层显式附带原生 schema，以原生模型校验；对于合法单条／列表补 `entries` 外层，无损保留字段。其余格式错误最多 3 次额外修复，无默认记忆事实；耗尽保留错误并暂停。**10 项原生测试通过**，日志 `.mematlas/memora-efficiency-final-native.log`，覆盖未结构化调用保持原消息、JSON object/schema、封套转换、修复成功和次数耗尽。试跑原始契约 metadata 保存在 `reviewed-memora-json-keyword-*`，每次失败响应成本保留。

最终受验套件已完成，`suite.json` 为 `completed`；五方法均 2 例、2 轮、有效评分和学习，首例正常暂停／恢复，合计 10 次计划诊疗。逐轮结果在 `efficiency-rounds.csv/json`，机器校验在 `smoke-verification.json`。记忆侧与完整流程的主要观测如下（秒；存储为 MiB）：

MemMachine 的 Round 2 实测包含 `memory_background_active_s=112.95`，说明后台语义摄取与前台等待重叠；其 memory 主指标取并集，不能把分项相加。MemOS、Mem0、EMem、Memora 此次短链未产生可观测后台活动。以上数值是带故障恢复和实现兼容修补的工程试跑，不能作为五方法效率排名；正式 5×20 必须使用新的空目录和最终代码重新开始。

最终只读验证确认四个受管端口均已停止，模型目录仍存在且 fingerprint 未变；硬件和运行时清单为 `hardware-after-smoke.json`。代码在试跑后还增加了请求按 round 的实际去重归因、失败 attempt 账本合并、完整 Memora LRU 检查点和医生 HTTP 状态／请求耗时记录；这些变化及限制见 `final-code-validation.json`。旧 Memora 试跑检查点没有完整 LRU，最终读取器按约定拒绝自动迁移，正式实验从空库开始。

Memora 最终 LRU 修补的原生测试 **10 passed**（`.mematlas/memora-efficiency-cache-final-v2.log`）：以原生缓存 API 和已存向量建立非空 LRU，禁止模型调用后恢复，缓存内容与顺序一致。MemMachine 完整存储根目录检查器修补后原生测试 **9 passed**（`.mematlas/memmachine-efficiency-inspector-final.log`）。这两项试跑后的生命周期／测量修改没有额外运行付费病例，不能宣称最终每个字节版本已重新实跑十例。

请求费用必须读取 `actual-requests.json` 的去重记录及 `efficiency-rounds.*` 的 `actual_*` 列。恢复后原有 callback-window 统计只包含该 attempt 剩余工作，可能出现某轮医生调用为零；它不是全轮真实调用量。最终报告通过业务病例、operation ID 和完整活动区间归因，十轮请求均成功归因，`request-attribution.json` 中未归因请求数均为零。费用缺少价格配置时保持未知，失败请求未知 usage 不填零当作已知。

时间的已知限制：Mem0 较早发生的自动恢复退避在新的计时钩子加入前，旧 round total 未含该段等待；原日志仍保留，不能补造精确时间。最终代码已用受控测试验证新运行纳入自动等待、排除人工暂停；此差异也是本套数据只作工程验收的原因。

最终十轮共归因 1,270 条去重实际请求记录（含前期失败和格式修复），不是 1,270 次诊疗。`smoke-verification.json` 断言每方法两份临床结果在跨 attempt 复制后保持一致、两例均完成评分／学习、事件身份唯一、累计 token 连续增长、前后台并集不超过分项之和、十轮计时事件闭合。这里的计时闭合不消除上文已说明的早期未装钩子时段限制。
