## 格式兼容修复

新增显式 `json_output_mode=json_unicode_v1`；缺省 `native` 仍保持旧调用方式。固定的官方 EMem 源码未修改，仍使用原生 EDU 抽取、事件／实体抽取、图构建、候选筛选与检索排序；不减少候选预算、不替换检索器、不截断轨迹。

在适配器模型传输边界：

- 启用 JSON object 模式，要求 Unicode 直接输出，正确处理内嵌引号和反斜杠。候选列表 JSON 仅更换 Unicode 编码写法，解码后字符串逐字相同。
- 使用实际官方 Pydantic schema 校验响应。EDU 筛选沿用官方 `difflib.get_close_matches(n=1, cutoff=0.85)` 映射规则，实际返回原候选对象和正文；不引入更严格的逐字输出门槛。无法按原生规则映射到候选的输出需要修复。
- 初次响应外最多三次格式修复，逐次保存请求、响应、错误、上下文和 usage。传输层仍独立执行有界重试。
- 遇到输出截断，修复阶段可将输出预算从 8192 增至 16384、最高 32768；全部实际开销入账，不通过截断正文制造提速。
- 修复耗尽进入可恢复暂停，不能依靠上游宽松兜底把格式错误当成成功。
- 快照记录 `adapter_profile`；禁止把旧格式配置的快照自动载入新配置。

受控验收：12 项 EMem 测试通过，覆盖真实官方构图／检索、缓存、零模型恢复、新格式原生 schema、非法 JSON／类型／候选修复、截断预算、耗尽暂停及每次响应留存。公共回归 59 项通过；新增串行门禁单独验证。
