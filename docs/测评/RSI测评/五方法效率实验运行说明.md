# 五方法血液科 RSI 效率实验

入口：`scripts/openhospital-memory-efficiency.py`。这是五方法串行队列，与历史 Mem0 三条件启动器分开。

## 环境

使用 Python 3.12。五方法各用 `.venv-memos`、`.venv-mem0`、`.venv-memmachine`、`.venv-emem`、`.venv-memora`；原生依赖锁与源码固定版本见各方法目录及 native 适配验收文档。

实验父进程使用 `.venv-adapters`，独立 embedding 服务使用 `.venv-embedding`：

```powershell
python -m venv .venv-adapters
.venv-adapters/Scripts/python.exe -m pip install -r configs/openhospital/efficiency-runner-requirements.lock.txt
python -m venv .venv-embedding
.venv-embedding/Scripts/python.exe -m pip install -r configs/openhospital/efficiency-embedding-requirements.lock.txt
```

在被 Git 忽略的 `integrations/openhospital_runtime/.env.local` 配置 `MODEL_API_KEY`。不要把密钥写入跟踪的 `.env.example`。
读取已有 `models/Qwen3-Embedding-0.6B`，不下载、不删除模型。默认 embedding 18766、医院 18001、Neo4j Bolt 18687／HTTP 18474，均仅监听本机。可以通过 `--embedding-port`、`--hospital-port`、`--bolt-port`、`--neo4j-http-port` 指定未占用端口；`--embedding-python` 指定独立解释器。恢复读取原清单中的设置。

Neo4j 需要已安装 Java 21。运行器复用经官方 SHA256 验证的便携发行包，给每套实验建立独占实例，不复制旧数据库。每个方法完整结束并释放 worker／后台任务后才启动下一个方法。

## 产物与恢复

`suite.json` 保存固定方法顺序、名单及哈希、模型环境、源文件签名和队列位置。`suite.lock` 是操作系统排他锁，不能通过删文件绕过运行中的 owner。

每方法 `attempt-NNN/config.json`、`worker.log`、`worker-result.json`、`preparation.json`、`evaluation/` 保存对应配置、日志、冷缓存／预热信息、临床结果与 checkpoint。各 attempt 的原生状态互相隔离；MemOS 重新打开本实验独占 namespace，再从有效快照替换图状态，避免物理库中遗留恢复副本。

`activity/events-PID.jsonl` 保存开始／结束事件及心跳。`measurement-0.json` 和逐轮 `measurement-N.json` 保存新增事件身份账本、规范化 payload token、全部原生正文层、数据库／索引／WAL 文件列表、内存状态序列化大小、操作延迟和计时覆盖标记。

`efficiency-rounds.json/csv` 和 PNG 报告包括逐轮与累计记忆耗时、总流程耗时、存储／正文增长和诊疗表现。存储／正文在每个病例检查点后更新，显示最近测量病例和后台待处理状态；原始评分与调用账本在各方法 evaluation 中保留。没有足够数据时不生成虚假的完整曲线。

跨 attempt 的整轮调用量读取 `actual_*` 列，完整实际请求见 `actual-requests.json`，归因覆盖见 `request-attribution.json`。恢复后的旧 callback-window 字段只描述该段剩余工作，不能用作整轮调用量。后台请求按业务病例、operation ID 及活动区间归因，未能归因的请求单列，不丢弃。硬件信息随新运行 preflight／suite 保存。

Memora 完整检查点包含向量、关系、BM25 重建所需原始顺序与 embedding LRU 内容／顺序。早期缺少 `cache_version=1` 的开发检查点不自动迁移。最终受验十例结果、工程修复过程及试跑后受控修补边界见 `20261106_五方法效率执行器验收.md`。

临时 API 故障每逻辑请求最多 8 次；用尽后在同一完整病例位置最多自动恢复 3 次（30／60／120 秒），无进展则保持 `PAUSED`。永久配置错误直接保留现场。人工恢复须先解决错误原因，源文件／模型／名单变更会拒绝继续。失败 attempt 的活动时间、调用与 payload 保留，已提交事件通过恢复后的公共状态去重。

硬杀进程可能留下未闭合计时事件；报告用最后心跳作已观测下界，尾段没有可证明的上界，不宣称精确耗时。后台可能与诊疗重叠，不能将总时间减去记忆时间当作医院纯耗时。

JSON 修复仅限格式与合法目录选择；原响应加最多 3 次额外修复，保留合法部分、过滤重复，耗尽后从尚未执行的合法目录选项兜底。目录耗尽进入诊断，不伪造检查结果、患者事实或评分。

`activity/cases/case-0000.json` 是空库基线，`case-0001.json`～`case-0100.json` 为病例采样；每个文件带完整性校验和提交检查点身份。新增经历、完整载荷、正文和库大小每病例更新。即使库存储不变，也保留该病例点。轮末排空后更新该轮最后一个病例点，不额外增加点。

逐病例采样不额外调用模型或强制后台排空；等待已在运行的后台批次停稳后只读测量，记录待处理队列。纯采样时间单列，不归因于记忆算法耗时。恢复先补提交后尚未采样的病例点，已完成的病例与 token 事件不重复累计。

`efficiency-cases.json/csv` 与 `storage_bytes.png`、`memory_text_tokens.png` 基于逐病例点；`efficiency-rounds.json/csv` 及时间／表现图仍基于完整轮次。初次测量前显示 `--`，不伪造数值。评分原始分数为 0–1，准确率和覆盖率显示百分比，耗时显示 `HH:MM:SS`。

测试入口完成受控测试后默认清理本次成功的 pytest 临时目录，失败时保留；需要查看成功测试现场时传 `--keep-temp`。实验结果、模型、依赖环境和历史验收不会被此逻辑清理。

## 2026-11-08：显示故障隔离与完成后回收

进度显示改为分段读取活动日志，计时摘要仅增量读取新增事件；显示异常写入 `observer-warning.json`，不会终止临床 worker。中断前未闭合计时区间保留不完整标志，人工暂停不计入有效运行时间。

每个方法完整完成后自动校验并回收该方法所有 attempt 的恢复检查点及 memory 快照副本；全部结果、指标、账本、轨迹和实际原生数据库保留。未完成方法不清理。`<run>/<method>/checkpoint-cleanup.json` 保存带哈希的清单与释放字节数；`suite.json` 的 `checkpoint_cleanup` 显示完成或待处理原因。完成标记先于清理落盘，所以清理中断不会重复诊疗。

源文件修复后的续跑仍有严格校验。此次修复的原文件、前后哈希和校验记录位于正式目录的 `repairs/20261108-observer-read`。框架只允许审计清单中的准确哈希变更，其他模型、医院状态、病例、反馈合同必须一致；原始检查点不修改，实际新源文件记录在恢复 attempt 的 `evaluation/source-compatibility.json`。
