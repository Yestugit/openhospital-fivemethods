# RiseMem 用户测评快速上手（改进版）

更新：2026-11-01。——11.01

**状态：统一测评与 QA 重构已实现。**本文说明当前用法，保留与[原文档](测评用户快速上手新.md)的对照备注。——11.01

用户提供 Memory 配置、任务数据和答题模型或 Agent，框架负责组织实验、执行、评分和保存结果。

```text
选择实验安排 → 配置 Memory → 准备 Benchmark → 配置答题模型或接入 Agent
→ 统一配置实验 → 执行（自动检查）→ 查看结果
```

Benchmark 提供案例和原生评分，Evaluation 组织实验，Memory 负责记忆操作，默认答题器或用户 Agent 负责完成案例。

## Quickstart：运行 LoCoMo Benchmark——11.01

使用 Mem0 学习 LoCoMo 历史，由 Qwen 回答前 5 道题并评分。以下示例已通过真实数据实跑。

在包含 `pyproject.toml` 的项目根目录安装：

```bash
python -m pip install -e ".[openai,benchmarks]" "qdrant-client>=1.12"
```

准备 [LoCoMo 原始数据 `locomo10.json`](https://github.com/snap-research/locomo/blob/main/data/locomo10.json)，放到 `agent-memory-benchmarks/LoCoMo/data/locomo10.json`；已有该文件可直接使用。

在运行脚本的同一个 PowerShell 窗口设置：

```powershell
$env:DASHSCOPE_API_KEY = "你的 Qwen API 密钥"
$env:OPENAI_BASE_URL = "https://dashscope.aliyuncs.com/compatible-mode/v1"
```

将以下代码保存为 `quickstart_eval.py`，在项目根目录执行 `python quickstart_eval.py`：

```python
import asyncio
from mematlas import MemAtlasConfig, ExperimentConfig, ExperimentRunner

llm = {"model": "qwen-plus", "base_url": None, "api_key_env": "DASHSCOPE_API_KEY"}
memory = MemAtlasConfig(
    method={"method_id": "mem0", "params": {"hybrid_search": False}},
    providers={
        "llm": llm,
        "embedding": {"model": "text-embedding-v4", "base_url": None,
                      "dimensions": 1024, "api_key_env": "DASHSCOPE_API_KEY"},
    },
)
experiment = ExperimentConfig(
    methods=(memory,),
    benchmark={"kind": "locomo", "path": "agent-memory-benchmarks/LoCoMo/data/locomo10.json"},
    answer_model=llm,
    test_limit=5,
)

result = asyncio.run(ExperimentRunner().evaluate(experiment))[0]
print(result.metrics)
print("结果目录：", result.run_metadata["output_dir"])
```

框架自动完成历史学习、检索、答题、评分和结果保存。输出评分与结果目录，目录中包含 `results.json` 和 `report.md`。

`base_url=None` 从环境变量读取服务地址。`test_limit=5` 只限制题数，仍需处理关联的完整历史；本次 Qwen 实跑包含 419 条历史，首次运行约 20 分钟，耗时随服务速度变化。

| 多检查点学习曲线 | 分批学习，在多个训练位置冻结测试，观察效果变化 |

## 2. 选择并配置 Memory

```bash
python -m mematlas methods list
python -m mematlas methods describe mem0
```

当前 `mem0`、`memrl`、`memoryos` 标记为 `interface_v2`；标记为 `migration_required` 的方法仍需迁移。所选方法的参数、依赖和反馈要求以 `describe` 输出及 `methods/<method_id>/method.yaml` 为准。

新建 `configs/mem0.json`，第 5 步通过 `MemAtlasConfig.load("configs/mem0.json")` 读取：

```json
{
  "method": {"method_id": "mem0", "params": {"top_k": 3}},
  "providers": {
    "llm": {
      "model": "Memory 使用的模型",
      "base_url": "模型服务地址",
      "api_key_env": "MODEL_API_KEY"
    },
    "embedding": {
      "model": "Embedding 模型",
      "base_url": "Embedding 服务地址",
      "api_key_env": "MODEL_API_KEY",
      "dimensions": 1024
    }
  },
  "scope": {"user_id": "benchmark"}
}
```

替换方法及模型参数，Embedding 维度须与实际模型匹配。按方法说明安装额外依赖，然后设置密钥：

```powershell
$env:MODEL_API_KEY = "你的 API 密钥"
```

## 3. 选择并准备 Benchmark

在第 5 步的 `ExperimentConfig(..., benchmark={"kind": ..., "path": ...})` 中指定数据类型和本地路径：

| `benchmark["kind"]` | 用户准备的数据 | 主要评分 |
|---|---|---|
| `locomo` | LoCoMo 原始 JSON | 类别问答 F1、检索召回率 |
| `longmemeval` | LongMemEval 原始 JSON | 会话检索指标，可选 LLM 答案判分 |
| `custom` | 自定义 JSON 或 JSONL | 通用指标 |

LoCoMo、LongMemEval 当前只有 `test/all` 划分；训练后冻结测试需另备训练数据。训练与测试需要复用记忆时，应配置可共享该记忆的 `scope`。

自定义 JSON 的基础格式如下：

```json
[
  {
    "case_id": "case-001",
    "split": "test",
    "scope": {"user_id": "alice"},
    "history": [{"event_id": "message-001", "role": "user", "text": "Helios 的端口是 8443。"}],
    "query": "Helios 的端口是多少？",
    "reference": "8443"
  }
]
```

`history` 是 Memory 可使用的历史，`query` 是任务输入，`reference` 留给评分。Python 适配器统一提供 `BenchmarkCase(case_id=..., query=..., history=..., scope=..., reference=..., episode=...)`；`episode` 可携带完整经历和真实反馈。

## 4. 接入任务执行逻辑

| 案例执行方式 | 用户提供 | 框架负责 |
|---|---|---|
| 内置问答流程 | `ExperimentConfig(..., answer_model=...)` | 选择默认 QA 或方法 QA，完成案例，交由评测层评分 |
| 自己的 Agent | `agent(case, memory) -> MemoryEpisode` | 组织实验，提交训练经历并评分 |

普通问答用户配置 `answer_model` 即可。答题模型与第 2 节 Memory 内部模型分别配置。

**默认 QA、方法 QA、用户 Agent 统一采用 `(case, memory) -> MemoryEpisode`。**`evaluation/qa.py` 的 `DefaultQA` 集中完成：

```text
检索记忆 → 组装提示 → 模型回答 → 返回经历及实际使用的记忆贡献
```

评测层统一转换为 `Prediction`，组织计时、评分和结果保存。——11.01

**不同 Memory 方法的 QA 接入规则：**

| 方法的实际需求 | 使用方式 |
|---|---|
| 只需在运行前填写不同的模型、阈值、算法参数等配置 | **使用默认 QA**，方法读取自己的配置 |
| 运行时需要的数据，已有公共字段或扩展数据能够直接提供，例如任务、轨迹、真实反馈、检索条件 | **使用默认 QA**，完整传递这些数据 |
| 方法内部能够自行完成特殊处理、更新或演化 | **使用默认 QA**，操作由方法内部完成 |
| 运行时需要额外采集、计算或组织方法专有数据，现有公共流程无法提供 | **编写该方法的 QA 接入代码**，补充数据获取、处理和传入 |
| 必须由 QA 主动调用特有操作，或使用方法自身的特殊答题机制 | **编写该方法的 QA 接入代码**，补充必要执行步骤 |

**方法集成开发者**按需在 `methods/<方法>/qa.py` 中继承 `DefaultQA`，并在方法插件中声明 `qa_factory = "模块路径:QA类名"`。框架自动选择该实现；未声明时使用 `DefaultQA`。**普通测评用户无需编写或选择 QA。**——11.01

| 方法 | 当前 QA |
|---|---|
| Mem0、MemoryOS | `DefaultQA` |
| MemRL | `MemRLQA`：复用默认答题，补充各归属最后一条训练经历的结束标记 |

**方法 QA 怎么写（方法集成开发者）：**只覆盖必要步骤，下面以现有 MemRL 接入为例：

```python
# methods/memrl/qa.py
from dataclasses import replace
from mematlas.evaluation import DefaultQA

class MemRLQA(DefaultQA):
    @staticmethod
    def prepare_episode(case, episode, *, last_for_scope):
        if not last_for_scope:
            return episode
        return replace(episode, extensions={
            **episode.extensions,
            "memrl": {**episode.extensions.get("memrl", {}), "end_of_training": True},
        })
```

在现有 `MemRLPlugin` 类中声明：

```python
qa_factory = "mematlas.methods.memrl.qa:MemRLQA"
```


其他必要差异可覆盖 `async retrieve(case, memory)` 或 `messages(case, contribution)`；需要特殊执行流程时，再覆盖 `async __call__(case, memory)`，仍返回 `MemoryEpisode`。——11.01

`extensions` 只负责携带专有数据。数据已经准备好时可以直接传递；需要新增代码才能取得或整理数据时，应完成对应的方法专属接入。

方法必需的真实数据无法取得时，应明确说明缺失条件，该组合暂不声明支持。——11.01

自定义 Agent 负责检索、模型调用、工具或环境交互，返回包含实际轨迹、最终结果和实际使用记忆贡献的 `MemoryEpisode`。按方法要求提供真实反馈。

**实验层负责历史导入、学习提交、检查点、冻结与恢复。**已有完整训练经历直接交给 `Memory.learn()`；需要重新执行训练任务时，由用户 Agent 返回实际经历。方法 QA 可在提交前整理必要数据。Agent 避免重复提交学习，冻结测试不学习测试经历。——11.01

> 原本：手动创建答题器，完整 Agent 另选 `interactive_agent` 协议。改进后：默认问答流程或单案例 Agent 接入，实验安排在第 1 节选择。

## 5. 配置并运行测评

### 5.1 统一配置与执行

普通测评与连续学习使用同一套实验配置，统一通过 `ExperimentRunner.evaluate(...)` 执行。

| 配置内容 | 使用约定 |
|---|---|
| Memory 方法 | 复用第 2 节的配置；比较多个方法时提供多份配置 |
| Benchmark | 指定数据类型、路径和必要的数据划分 |
| 实验安排 | 选择第 1 节的三种安排之一 |
| 案例执行 | 配置答题模型，或接入自己的单案例 Agent |
| 连续学习 | 补充训练数据、测试数据和测试位置 |
| 输出目录 | 在实验配置中统一指定 |

调用方式如下，省略具体配置字段：

```python
experiment = ExperimentConfig(...)
runner = ExperimentRunner()
results = await runner.evaluate(experiment)

# 使用自己的 Agent 时，仍调用同一个执行入口：
# results = await runner.evaluate(experiment, agent=my_agent)
```

内部执行链：

```text
ExperimentRunner.evaluate()
    → validation.py：检查条件
    → execution.py：组织学习与测试，调用 QA／Agent
    → MemoryEpisode → Prediction
    → Evaluator：评分 → 保存结果
```

`cases.py` 已整理为 `execution.py`，旧 `runner.py` 与 `protocols/` 的有效逻辑已归入执行和检查模块。——11.01

独立的 `ExperiencePlan` 用户入口与重复运行包装已清理。用户无需为连续学习另行构造 Memory，也无需在运行时重复填写输出目录。

> 原本：普通测评与连续学习分别配置、拼装。改进后：一套实验配置、一个执行入口，不保留不必要的旧用法兼容。

### 5.2 多检查点调度

用户提供训练数据、测试数据和测试位置，普通用户无需编写 `train_batch`、`test_batch`。

框架负责分批执行、学习提交、检查点冻结测试和指标汇总。分批、进度统计、失败处理及保存频率采用明确默认值，减少必填选择。

记忆方法自身的学习批次和演化时机继续遵循原生规则。

> 原本：用户填写调度参数并实现批次回调。改进后：框架组织通用调度，用户提供必要的实验数据与安排。

### 5.3 检查与运行

`evaluate(...)` 自动完成必要检查；`check(...)` 保留为按需使用的提前检查接口。缺少必要数据、反馈或方法能力时，明确说明缺失项。

**框架开发者负责内置 QA 的接入与验证。**每个声明支持的方法与 Benchmark 组合，都应验证：所需数据能够取得、参数完整传入、必要步骤正确执行、记忆输出正确使用、原生更新规则得到保留。

用户按说明提供配置与数据后，应能直接运行，无需自行补写 QA 接入代码。——11.01

> 原本：示例先调用 `check(...)`，再调用 `evaluate(...)`。改进后：主流程直接执行，提前检查按需使用。

```python
saved = ExperimentRunner().results("outputs/locomo-mem0")
```

### 6.1 通用指标——11.01

| 学术维度 | 指标与统计口径 | 实现情况 |
|---|---|---|
| **任务性能** | 完全匹配率（Exact Match，EM）：标准化后的答案完全匹配比例 | 已有 |
| | 答案词元级 F1（Token-level F1）：预测答案与参考答案的词元重合程度 | 已有 |
| **学习效率** | 学习曲线：横轴为累计完成的训练案例数，纵轴为固定测试集上的主评分 | 已有检查点结果 |
| **时间效率** | 记忆构建／学习总耗时（s） | 已有，按构建／训练阶段分别汇总 |
| | 平均检索延迟（ms／次） | 已有 |
| | 平均问题响应时间（s／题）：开始处理问题至生成最终答案 | 已有，统一记录单题处理至回答完成的耗时 |
| **计算开销** | 模型输入／输出 Token 总数（tokens） | 已有，记录采集覆盖率；采集不完整时保留已知用量 |
| | LLM 请求次数、Embedding 请求次数（次） | 已有，分别汇总 |
| **空间开销** | 峰值常驻内存（Peak RSS，MiB）：评测进程及其子进程的采样峰值 | 已有 |
| | 记忆数据存储量（MiB）：记忆数据文件占用，排除日志和重复快照 | 已有，按记忆数据范围统计 |

模型用量按 Memory、答题、判分分别统计；建库和判分耗时单独记录。Token 与请求次数作为计算开销的代理，比较时记录模型与运行条件。去掉金额费用，保留完成率、失败数等运行记录。

### 6.2 Benchmark 专用指标——11.01

| Benchmark | 学术维度 | 指标 |
|---|---|---|
| **LoCoMo** | 任务性能 | 原生问答得分：总体及各题型得分，按题型采用 F1 或拒答判定 |
| | 检索质量 | 证据召回率：实际使用的记忆覆盖标注证据的比例 |
| **LongMemEval** | 任务性能 | LLM 判分准确率：总体、普通问题、拒答问题及各题型；需配置判分器 |
| | 检索质量 | 会话召回率；Recall-any@k、Recall-all@k、NDCG@k |
| **OpenHospital** | 任务性能 | 诊断准确率；检查精确率、召回率、无检查率；治疗总分、安全性、有效性匹配度、个性化；综合临床分 |
| | 持续学习表现 | 首末检查点得分增益；按训练区间长度归一化的学习曲线面积 |
| | 学习效率 | 每 100 次训练交互的平均得分增益 |
| | 学习稳定性 | 最大得分回落：相对此前最高检查点得分的最大下降幅度 |

自定义 JSON／JSONL 当前使用通用指标，无额外原生评分。

LongMemEval 的 `NDCG@k` 已采用标准对数折扣计算。——11.01
