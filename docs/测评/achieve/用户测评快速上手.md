# RiseMem 用户测评快速上手

更新：2026-10-31

本文面向第一次使用 RiseMem 的用户，说明如何准备 Benchmark、检查 Memory 配置、运行测评和查看结果。

## 1. 测评流程

```text
Memory 配置
    ↓
Benchmark 数据集 → BenchmarkCase
    ↓
EvaluationProtocol
    ↓
Memory：observe / retrieve / learn
    ↓
QA Answerer 或 Agent
    ↓
Prediction
    ↓
Benchmark 原生评分、通用指标与资源统计
    ↓
EvaluationResult
```

Benchmark 提供案例和原生评分，Evaluation 组织执行流程，Memory 负责记忆操作，Answerer 或 Agent 负责生成结果。

## 2. 安装与查看方法

在包含 `pyproject.toml` 的项目根目录执行：

```bash
python -m pip install -e ".[yaml,openai,benchmarks]"
python -m mematlas methods list
python -m mematlas methods describe mem0
```

方法的参数、依赖、支持的操作和输入要求以 `methods/<method_id>/method.yaml` 及方法包说明为准。

需要模型服务时设置密钥：

```powershell
$env:MODEL_API_KEY = "your-key"
```

## 3. Runner 接口

测评执行统一使用 `ExperimentRunner`：

```python
from mematlas import ExperimentRunner

runner = ExperimentRunner()
```

| 接口 | 用途 |
|---|---|
| `runner.check(experiment, ...)` | 检查方法、Benchmark、协议和依赖 |
| `await runner.evaluate(experiment, ...)` | 执行普通 Benchmark 或多方法比较 |
| `await runner.evaluate(plan, ...)` | 执行连续学习、检查点和冻结测试 |
| `runner.results(path)` | 读取已有结果 |

`ExperimentConfig`、`ExperimentSpec` 和 `ExperiencePlan` 表达不同实验类型；真正的执行入口保持为 `runner.evaluate()`。

普通 Benchmark 使用 `ExperimentConfig`：

```python
from mematlas import ExperimentConfig, ExperimentRunner

experiment = ExperimentConfig.load("configs/experiment.yaml")
runner = ExperimentRunner()

check = runner.check(experiment, answerer=answerer)
if not check["ready"]:
    raise RuntimeError(check)

results = await runner.evaluate(experiment, answerer=answerer)
```

需要 Agent 自己完成检索、模型调用、工具执行和学习数据组织时，传入：

```python
results = await runner.evaluate(experiment, agent=agent)
```

回调约定：

```python
answerer(case, contribution) -> Prediction
agent(case, memory) -> MemoryEpisode
```

`answerer` 接收案例和检索结果，返回 `Prediction`；`agent` 自己使用 `memory`，完成任务后返回 `MemoryEpisode`。

## 4. 配置 Memory

新建 `configs/mem0.json`：

```json
{
  "method": {
    "method_id": "mem0",
    "params": {
      "implementation_mode": "offline",
      "infer": false,
      "write_policy": "episode",
      "top_k": 3
    }
  },
  "scope": {
    "user_id": "benchmark",
    "agent_id": "qa-reader"
  },
  "runtime": {
    "artifact_dir": ".mematlas/runs/mem0"
  }
}
```

先检查配置：

```bash
python -m mematlas check configs/mem0.json
```

输出中的 `ready` 为 `true` 后再运行测评。`offline` 只适合检查流程，正式测评应按方法说明配置真实模型、Embedding 和依赖。

## 5. 准备 Benchmark 数据

当前入口支持：

1. `locomo`
2. `longmemeval`
3. `custom`：JSON 或 JSONL

检查数据：

```bash
python -m mematlas benchmark custom data/cases.json --limit 5
```

自定义 JSON 的最小格式：

```json
[
  {
    "case_id": "case-1",
    "split": "test",
    "history": [
      {
        "kind": "message",
        "role": "user",
        "content": "Helios 的服务端口是多少？"
      },
      {
        "kind": "message",
        "role": "assistant",
        "content": "端口是 8443。"
      }
    ],
    "query": "Helios 的服务端口是多少？",
    "reference": "8443"
  }
]
```

每个案例至少提供：

| 字段 | 作用 |
|---|---|
| `case_id` | 案例唯一 ID |
| `history` | 提供给 Memory 的历史事件 |
| `query` | 当前检索问题 |
| `reference` | 评分参考答案 |
| `split` | 数据划分，省略时默认为 `test` |

## 6. 运行测评

### 6.1 Streaming

逐案例导入历史、检索记忆、生成答案并评分：

```bash
python -m mematlas run \
  --config configs/mem0.json \
  --benchmark custom \
  --data data/cases.json \
  --split test \
  --protocol streaming \
  --report-dir .mematlas/reports/mem0
```

### 6.2 Experience

先使用 `train` 数据学习，再在 `test` 数据上冻结记忆评测：

```bash
python -m mematlas run \
  --config configs/mem0.json \
  --benchmark custom \
  --data data/cases.json \
  --train-split train \
  --split test \
  --protocol experience \
  --report-dir .mematlas/reports/mem0-experience
```

### 6.3 比较多个方法

重复 `--config`：

```bash
python -m mematlas run \
  --config configs/mem0.json \
  --config configs/memoryos.json \
  --benchmark custom \
  --data data/cases.json \
  --protocol streaming \
  --report-dir .mematlas/reports/compare
```

命令行是 `ExperimentRunner` 的使用封装。需要自定义 Answerer、Agent 或连续学习回调时，使用 Python 接口。

## 7. 连续学习与冻结测试

使用 `ExperiencePlan` 描述训练案例、测试案例和检查点，仍通过 `runner.evaluate()` 执行：

```python
results = await runner.evaluate(
    plan,
    memory=memory,
    output_dir=".mematlas/runs/experience",
    train_batch=train_batch,
    test_batch=test_batch,
    resume_from=None,
)
```

```text
训练批次 → 保存检查点 → 冻结测试 → 继续训练 → 下一检查点
```

回调约定：

```python
train_batch(case_ids, memory, batch_index) -> BatchResult
test_batch(case_ids, memory, checkpoint_index, split) -> dict
```

`ExperienceRunner` 负责批次、检查点、冻结和恢复；回调负责实际 Agent 与环境交互。

## 8. 查看结果

```bash
python -m mematlas results .mematlas/reports/mem0
```

结果中重点查看：

1. `metrics`：通用指标和 Benchmark 原生指标。
2. `failures`：失败阶段、案例和错误原因。
3. `resource_metrics`：操作次数、耗时、Token、费用和存储。
4. `predictions[].applied_memory`：实际使用的记忆贡献。

常见产物包括 `results.json`、`report.md`、逐案例预测、操作追踪、`usage.jsonl` 和方法状态文件。

## 9. 当前版本说明

当前分支的内置 Benchmark 适配器仍有旧数据模型引用，核心 v2 迁移尚未完成。`benchmark --help` 可以查看命令参数，实际加载内置 Benchmark 前需要完成适配迁移；迁移完成后，本页第 5、6 节命令作为标准入口。

OpenHospital RSI 使用独立的场景入口和 `ExperienceRunner`，属于连续交互实验，不属于本页的经典 Benchmark 快速上手流程。
