# RiseMem 用户测评快速上手

更新：2026-10-31

用户提供 Memory 配置、任务数据和答题模型或 Agent，框架负责执行、评分和保存结果。

```text
选择测评任务 → 配置 Memory → 准备数据 → 接入答题逻辑
→ 配置实验 → 检查 → 执行 → 查看结果
```

> 当前内置 Benchmark 加载受阻，具体见第 9 节。以下按现有代码介绍接口与使用流程。
>
> ## 1. 测评流程

```text
Memory 配置
    ↓
Benchmark 数据集 → BenchmarkCase
    ↓
EvaluationProtocol
    ↓
Memory：observe / retrieve / learn
    ↓
QA Answerer 或 Agent
    ↓
Prediction
    ↓
Benchmark 原生评分、通用指标与资源统计
    ↓
EvaluationResult
```

Benchmark 提供案例和原生评分，Evaluation 组织执行流程，Memory 负责记忆操作，Answerer 或 Agent 负责生成结果。

## 1. 安装并选择测评任务

在包含 `pyproject.toml` 的项目根目录执行：

```bash
python -m pip install -e ".[yaml,openai,benchmarks]"
```

| 测评需求 | 配置入口 |
|---|---|
| 把已有历史交给 Memory，再检查能否回答相关问题 | `ExperimentConfig(..., protocol="streaming_memory")` |
| 先学习一批训练经历，再冻结记忆测试一次 | `ExperimentConfig(..., protocol="experience_train_test", train_split="train")` |
| 分批学习，在多个检查点冻结测试，观察效果变化 | `ExperiencePlan(train_ids=..., primary_test_ids=..., checkpoints=..., ...)` |

## 2. 选择并配置 Memory

```bash
python -m mematlas methods list
python -m mematlas methods describe mem0
```

当前 `mem0`、`memrl`、`memoryos` 标记为 `interface_v2`；标记为 `migration_required` 的方法仍需迁移。所选方法的参数、依赖和反馈要求以 `describe` 输出及 `methods/<method_id>/method.yaml` 为准。

新建 `configs/mem0.json`，第 5 步通过 `MemAtlasConfig.load("configs/mem0.json")` 读取：

```json
{
  "method": {"method_id": "mem0", "params": {"top_k": 3}},
  "providers": {
    "llm": {
      "model": "Memory 使用的模型",
      "base_url": "模型服务地址",
      "api_key_env": "MODEL_API_KEY"
    },
    "embedding": {
      "model": "Embedding 模型",
      "base_url": "Embedding 服务地址",
      "api_key_env": "MODEL_API_KEY",
      "dimensions": 1024
    }
  },
  "scope": {"user_id": "benchmark"}
}
```

替换方法及模型参数，Embedding 维度须与实际模型匹配。按方法说明安装额外依赖，然后设置密钥：

```powershell
$env:MODEL_API_KEY = "你的 API 密钥"
```

## 3. 选择并准备 Benchmark

在第 5 步的 `ExperimentConfig(..., benchmark={"kind": ..., "path": ...})` 中指定数据类型和本地路径：

| `benchmark["kind"]` | 用户准备的数据 | 主要评分 |
|---|---|---|
| `locomo` | LoCoMo 原始 JSON | 类别问答 F1、检索召回率 |
| `longmemeval` | LongMemEval 原始 JSON | 会话检索指标，可选 LLM 答案判分 |
| `custom` | 自定义 JSON 或 JSONL | 通用指标 |

LoCoMo、LongMemEval 当前只有 `test/all` 划分；训练后冻结测试需另备训练数据。训练与测试需要复用记忆时，应配置可共享该记忆的 `scope`。

自定义 JSON 的基础格式如下，适配器的当前限制见第 9 节：

```json
[
  {
    "case_id": "case-001",
    "split": "test",
    "scope": {"user_id": "alice"},
    "history": [{"event_id": "message-001", "role": "user", "text": "Helios 的端口是 8443。"}],
    "query": "Helios 的端口是多少？",
    "reference": "8443"
  }
]
```

`history` 是 Memory 可使用的历史，`query` 是任务输入，`reference` 留给评分。Python 适配器统一提供 `BenchmarkCase(case_id=..., query=..., history=..., scope=..., reference=..., episode=...)`；`episode` 可携带完整经历和真实反馈。

## 4. 接入任务执行逻辑

| 执行方式 | 接口 | 用途 |
|---|---|---|
| 框架答题器 | `answerer(case, contribution) -> Prediction` | 标准问答 |
| 用户 Agent | `agent(case, memory) -> MemoryEpisode` | 多步交互、工具或环境任务 |

### 问答测评：创建答题器

```python
from mematlas.evaluation.qa import memory_qa_answerer
from mematlas.providers import OpenAICompatibleLLM

llm = OpenAICompatibleLLM(
    model="答题模型名称",
    base_url="答题模型服务地址",
    api_key_env="MODEL_API_KEY",
)
answerer = memory_qa_answerer(llm, model=llm.model)
```

该模型负责回答问题；第 2 步的模型负责 Memory 内部处理。也可自行实现 `answerer(case, contribution) -> Prediction`，返回 `Prediction(case_id=..., output=..., reference=..., applied_memory=...)`。`applied_memory` 保留实际提供给模型的完整记忆贡献。

### 完整 Agent：提供自己的回调

配置：`ExperimentConfig(..., protocol="interactive_agent")`；执行：`await runner.evaluate(experiment, agent=my_agent)`。

实现 `my_agent(case, memory) -> MemoryEpisode`，在回调内完成检索、工具或环境交互，返回：

```python
from mematlas import MemoryEpisode

MemoryEpisode(
    episode_id=case.case_id,
    events=实际执行轨迹,
    output=最终结果,
    applied_memory=实际使用的记忆贡献,
    scope=case.scope,
)
```

按方法要求补充真实反馈。非冻结协议会自动将返回的经历交给 `memory.learn(...)`，回调中避免重复提交。需要只读执行完整 Agent 时，使用 `ExperimentConfig(..., metadata={"frozen": True})`。

## 5. 配置并运行测评

第 1 节第 1、2 项对应单评测点实验，第 3 项对应多检查点学习曲线实验。

| 第 1 节的测评任务 | 本节入口 |
|---|---|
| 1. 已有历史测评 | 5.1 单评测点实验 |
| 2. 训练后冻结测试 | 5.1 单评测点实验 |
| 3. 分批学习并多次测试 | 5.2 多检查点学习曲线实验 |

### 5.1 单评测点实验

在一个固定阶段对完整测试集评测，生成一组结果。一个评测点可以包含多个测试案例。

```python
import asyncio

from mematlas import MemAtlasConfig, ExperimentConfig, ExperimentRunner


async def main():
    experiment = ExperimentConfig(
        methods=(MemAtlasConfig.load("configs/mem0.json"),),
        benchmark={"kind": "locomo", "path": "data/locomo.json"},
        protocol="streaming_memory",
        split="test",
        output_dir="outputs/locomo-mem0",
    )

    runner = ExperimentRunner()
    report = runner.check(experiment, answerer=answerer)
    if not report["ready"]:
        raise RuntimeError(report)

    results = await runner.evaluate(experiment, answerer=answerer)

    for result in results:
        print(result.method_id, result.metrics, result.failures)


asyncio.run(main())
```

根据测评方式调整配置和执行参数：

| 测评方式 | `ExperimentConfig(...)` | `runner.evaluate(...)` |
|---|---|---|
| 已有历史测评 | `protocol="streaming_memory"` | `answerer=answerer` |
| 训练后冻结测试 | `protocol="experience_train_test", train_split="train"` | `answerer=answerer` |
| Agent 执行训练 | `protocol="experience_train_test", train_split="train"` | `answerer=answerer, agent=my_agent` |
| 完整 Agent 测评 | `protocol="interactive_agent"` | `agent=my_agent` |

比较多个方法时，在 `ExperimentConfig(methods=(配置1, 配置2))` 中传入多份 Memory 配置。

CLI 提供单评测点问答入口：

```bash
python -m mematlas run --config configs/mem0.json --benchmark locomo --data data/locomo.json --protocol streaming --split test --report-dir outputs/locomo-mem0
```

`--protocol streaming` 对应 `streaming_memory`，`--protocol experience` 对应 `experience_train_test`。完整 Agent 通过 Python 接入。

### 5.2 多检查点学习曲线实验

使用 `ExperiencePlan(...)`，在多个训练位置分别冻结测试，生成多组结果和学习曲线。

```python
import asyncio

from mematlas import MemAtlasConfig, Memory, ExperimentRunner
from mematlas.evaluation import ExperiencePlan


async def main():
    plan = ExperiencePlan(
        train_ids=("train-1", "train-2"),
        primary_test_ids=("test-1",),
        advanced_test_ids=(),
        batch_count=2,
        checkpoints=(0, 1, 2),
    )

    report = await ExperimentRunner().evaluate(
        plan,
        memory=Memory(MemAtlasConfig.load("configs/mem0.json")),
        output_dir="outputs/experience",
        train_batch=train_batch,
        test_batch=test_batch,
    )

    print(report["status"])


asyncio.run(main())
```

| 接口 | 用户负责 |
|---|---|
| `train_batch(ids, experience, batch_index)` | 执行训练任务并提交学习 |
| `test_batch(ids, experience, checkpoint, split)` | 在检查点执行测试并返回指标 |

框架负责分批训练、保存状态和测试期间冻结 Memory。

## 6. 查看结果

普通测评返回 `list[EvaluationResult]`，每个方法对应一个结果：

| 结果字段 | 内容 |
|---|---|
| `EvaluationResult.metrics` | 通用指标与 Benchmark 原生评分 |
| `EvaluationResult.predictions` | 逐案例输出、参考答案和实际使用的记忆 |
| `EvaluationResult.failures` | 失败案例和错误 |
| `EvaluationResult.resource_metrics` | 耗时、Token 和资源统计；费用需配置价格 |
| `EvaluationResult.run_metadata / traces` | 运行信息和操作记录 |

普通测评保存 `results.json`、`report.md` 和逐案例记录；连续学习返回报告字典，保存 `result.json`、`curve.json`、快照和用量记录。

读取已有结果：

```python
saved = ExperimentRunner().results("outputs/locomo-mem0")
```

CLI：`python -m mematlas results outputs/locomo-mem0`。先检查失败信息，再解释评分。

## 7. 当前代码限制

1. 内置 Benchmark 适配器仍引用已移除的 `ContentBlock` 等类型，标准数据加载目前会失败。
2. 自定义 JSON 适配器的旧 `outcome` 与当前 `BenchmarkCase.episode` 尚未对齐。
3. LoCoMo、LongMemEval 当前只有 `test/all`，训练后冻结测试需另备训练数据。OpenHospital 场景运行见同目录的 `RSI_OpenHospital_测评交接.md`。
