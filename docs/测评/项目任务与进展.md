# 测评：项目任务与进展

更新日期：2026-11-01。

## 1. 当前目标

维护经典 Benchmark 和 OpenHospital RSI 测评。**统一测评入口和 OpenHospital 小规模真实闭环已接通。**接下来完善参评方法适配与使用条件检查，确定正式实验配置，开展 RSI 效果对照。

## 2. 已明确的任务与当前情况

| 任务 | 当前进度 |
|---|---|
| 统一测评流程 | 三种实验安排共用配置、执行和结果入口；多检查点由框架调度 |
| 案例执行 | 内置问答流程已接通，也可传入已有 Agent |
| 医院场景接入 | 已接通统一配置、服务管理、三种病例流、反馈交付、冻结与恢复 |
| 公共职责整理 | 已复用公共经历记录和冻结保护，清理重复统计；方法专用字段移回方法适配 |
| 小规模真实运行 | Mem0 诊疗、评分、学习、冻结测试与恢复已完成 |
| 正式效果实验 | 已记录 `40×5` 参考方案，完整对照与多种子实验待开展 |

经典 Benchmark 当前支持 LoCoMo、LongMemEval 和自定义数据，统一使用 `ExperimentConfig`、`ExperimentRunner.check()`、`evaluate()` 和 `results()`。

Mem0、MemRL、MemoryOS 已声明新版接口；具体测评场景仍需满足方法的数据与能力要求。无记忆、BM25 及其他参评方法需完成新版接口适配后，再进入正式对照。

## 3. 当前问题与已有处理方向

**补齐逐 Benchmark 使用清单。**每个 Benchmark 都提供面向使用者的参数、可调用接口和使用条件清单，使用户能够据此配置与接入。突出必需与可选项，减少重复说明和内部实现细节。——10.30

| 内容 | 必要说明 |
|---|---|
| 参数 | 读取与评分参数的含义、类型、必填项及默认值 |
| 可调用接口 | 数据读取、任务交互、评分等实际开放接口及输入输出 |
| 调用要求 | 数据格式、必需步骤与可用评测流程 |
| 使用条件 | 所需 Agent 能力、反馈、评分器、模型、依赖与环境 |
| 最小示例 | 一条满足条件的评测流程 |

**配合组合条件检查。**与方法方向共同声明 Memory、Agent、Benchmark 和评测流程的必要条件，配合框架层阻止不满足条件的运行并说明缺失项。运行中才能确定的条件在相关操作前检查。完整清单与检查覆盖待落实。——10.30

**医院运行材料已收拢。**医院运行组件位于 `integrations/openhospital_runtime/`，场景适配位于 `integrations/openhospital/`；通过 `OpenHospitalServices(experiment)` 管理本地服务，由公共 `ExperimentRunner` 执行实验。交付时保留方法与模型配置、病例计划、运行记录和医院世界。

**新版小规模闭环已完成。**Mem0 已完成 1 次训练诊疗、训练前后固定测试和恢复运行，失败数为 0，临床评分覆盖率为 100%。配置与产物位置见[实验日志](实验日志.md)。正式 RSI 效果对照尚未开展。

**正式实验方案待固定。**已在 [OpenHospital RSI 快速上手（改进版）](OpenHospital_RSI快速上手_改进版.md)记录 `40×5` 参考方案；正式运行前固定病例名单、方法配置、模型、反馈安排与随机种子。

**正式实验继续记录完整进度。**分别记录完成诊疗数、有效评分数、已学习数和待反馈数；测试期间不学习，恢复时复用已完成的诊疗与评分。资源统计保留来源与覆盖情况，缺失项说明范围。

## 4. 执行顺序与完成条件

1. 完善参评方法与控制基线的新版适配，补齐 Benchmark 使用条件和必要检查。
2. 固定正式实验的病例名单、方法配置、模型、反馈安排与随机种子。
3. 按参考方案开展对照实验，记录固定测试曲线、临床评分、学习进度与资源用量。
4. 汇总多种子结果，分析经验复用、迁移、干扰和退化。
