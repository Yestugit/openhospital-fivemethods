# 测评入门

更新日期：2026-11-01。

## 1. 两类测评

**经典 Benchmark** 检查记忆对历史信息利用和回答效果的作用。当前代码支持 LoCoMo、LongMemEval 和自定义 JSON/JSONL；LoCoMo 提供文本与图文模式。

**OpenHospital RSI 测评** 固定医生 Agent，通过更换 Memory 观察连续诊疗中的经验学习、复用、迁移和退化。新版小规模真实闭环已接通，正式效果对照待开展。

## 2. 统一配置与实验安排

经典 Benchmark 与 OpenHospital RSI 共用 `ExperimentConfig` 和 `ExperimentRunner`。

| 实验安排 | 配置 |
|---|---|
| 给定历史，逐题检索并回答 | `ExperimentConfig(..., protocol="streaming_memory")` |
| 先学习训练经历，再冻结测试 | `ExperimentConfig(..., protocol="experience_train_test")` |
| 分阶段学习，在多个检查点冻结测试 | `ExperimentConfig(..., protocol="experience_learning_curve")` |

内置问答 Benchmark 可通过 `answer_model` 配置答题模型；使用已有 Agent 时，通过 `runner.evaluate(experiment, agent=...)` 接入。多检查点调度由框架完成。OpenHospital 使用 `experience_learning_curve` 和内置医生，一次运行一个 Memory 方法。

LongMemEval 默认使用 LLM judge，评分调用纳入用量记录。选择 Memory 和 Benchmark 时核对各自的数据、反馈与服务条件；使用清单和检查任务见[项目任务与进展](项目任务与进展.md)。

## 3. 医院环境与代码分工

医院运行组件统一保存在 [integrations/openhospital_runtime/](../../integrations/openhospital_runtime/)，与医院适配目录 [integrations/openhospital/](../../integrations/openhospital/) 并列。SDK、医生示例、服务源码、完整病例数据和分科室名单均在运行组件目录。

| 位置，均相对于框架仓库根目录 | 用途 |
|---|---|
| `integrations/openhospital/` | 医院场景适配与服务管理，接入公共 `ExperimentRunner` |
| `integrations/openhospital_runtime/run_openhospital_local.py` | 独立启动本地医院服务 |
| `integrations/openhospital_runtime/build_openhospital_department_ids.py` | 根据原始数据生成分科室名单 |
| `integrations/openhospital_runtime/department_patient_ids.json` | 各科室和划分的患者 ID |
| `integrations/openhospital_runtime/hospital-agent-sdk/` | 医院交互与调度 |
| `integrations/openhospital_runtime/hospital_agent_example/` | 医生 Agent、提示和配置 |
| `integrations/openhospital_runtime/hospital_service/` | 医院服务、评分与完整病例数据 |

在医院目录安装自己的依赖，并在该目录的 `.env.local` 配置 `MODEL_API_KEY`，可参考 `.env.example`。本地密钥文件不进入 Git。

```powershell
python -m pip install -r requirements.txt
```

使用 `OpenHospitalServices(experiment)` 根据实验配置启动所需服务、等待就绪，并在退出时关闭。配置好 `experiment` 和 `runner` 后，在异步函数中执行：

```python
from mematlas.integrations.openhospital import OpenHospitalServices

async with OpenHospitalServices(experiment):
    results = await runner.evaluate(experiment)
```

未配置最终额外测试时，不启动对应服务。医院世界目录用于保存环境状态，恢复运行时继续使用原目录。

需要重新生成名单时，在医院目录执行 `python build_openhospital_department_ids.py`，默认写回该目录的患者名单；`--output` 可指定输出位置。框架适配默认读取随附的医院目录。

## 4. 三种任务流

| 条件 | 交互方式 | 观察重点 |
|---|---|---|
| `repeated` | 固定患者多轮重新诊疗，每次保存独立回合 | 直接复用与反馈修正 |
| `novel_same_department` | 同科室不同患者依次诊疗 | 同领域经验迁移 |
| `novel_departments` | 不同科室患者按区块进入 | 跨科室迁移、干扰与退化 |

三种条件使用共同测试面板，训练、primary 和 advanced 的患者隔离。测试时冻结记忆和待反馈状态，评分只用于报告。重复病例的固定资料与动态问诊同时存在，需要分别观察训练病例表现和未见病例表现。

已记录 `40 例 × 5 阶段` 的参考方案：血液科新病例为主实验，重复病例为补充，跨科实验依次使用血液、呼吸、消化、内分泌和神经科。三种实验共用固定测试面板。

该方案尚未开展正式对照实验；代码默认规模仍为 `50 例 × 5 阶段`。具体名单与规模见 [OpenHospital RSI 快速上手（改进版）](OpenHospital_RSI快速上手_改进版.md)第 4.1 节。

## 5. 科室与病例选择

目前共有 19 科室，按单科室标签筛选并保留同科室合并症后，train / primary / advanced 分别为 9,010 / 1,000 / 640。

部分科室的可用病例量如下：

| 科室 | train | primary | advanced | 疾病标签数 |
|---|---:|---:|---:|---:|
| 儿科 | 205 | 28 | 17 | 15 |
| 血液科 | 448 | 37 | 27 | 22 |

选择时结合疾病范围、数量和实际诊疗评分可用性。口腔科、普外科、肾内科的 advanced 各只有 9 人，测试规模需与可用量匹配。

## 6. 评分、反馈和计算资源

主指标为诊断准确性、检查 precision 和治疗 overall score。当前默认奖励取三项等权平均，默认成功阈值为 0.5；方法变体或映射变化需说明。官方检查 precision 的有效分母不同，单独报告。

默认每例诊疗结束后生成临床评分与医生反思，并立即提交学习；批量、延迟模式调整反馈交付时机。分别记录完成诊疗数、有效评分数、已学习数和待反馈数。冻结测试不提交学习，评分缺失保留缺失状态。

最终公开指标保留临床评分、学习变化、记忆来源、Token、调用次数、耗时、内存和存储，不展示金额费用。准备、持续运行、冻结测试分别汇总，医生、Memory、医院模拟与评分分别归属。涉及本地训练时记录实际 GPU 资源；远端未测资源保留未测状态。

方法能够自行判断演化时机时，由内部触发；需要 Agent 主动通知时才调用 `evolve`，与检查点评测解耦。

## 7. 检查、运行与恢复

配置好 `experiment` 后，普通 Benchmark 在异步函数中使用：

```python
from mematlas import ExperimentRunner

runner = ExperimentRunner()
report = runner.check(experiment)
results = await runner.evaluate(experiment)
saved = runner.results(experiment.output_dir)
```

OpenHospital 运行时使用第 3 节的服务管理代码，检查和结果读取共用以上接口。

恢复时，通过 `ExperimentConfig.load(原运行目录)` 读取配置，设置新的输出目录，再调用 `runner.evaluate(..., resume_from=原运行目录)`；保留原记忆存储和医院世界。

完整配置示例分别见[测评用户快速上手新（改进版）](测评用户快速上手新_改进版.md)和 [OpenHospital RSI 快速上手（改进版）](OpenHospital_RSI快速上手_改进版.md)。实际验证记录见[实验日志](实验日志.md)。
