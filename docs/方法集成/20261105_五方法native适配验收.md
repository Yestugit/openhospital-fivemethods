# OpenHospital Memory v3 五方法适配

本轮工作从远端 `main@50f392087e2bd495d2d95831308a1b4c0434f16e` 开始，实施分支为
`codex/openhospital-memory-methods`。依据最新《1031方法书写约束》及开发者 README，直接封装固定
上游实现，默认复用公共 QA。本记录描述接入与验收，不确定正式实验的病例规模、预算、种子或对照方案。

## 来源与运行边界

| 方法 ID | 固定官方源码 | 原生路径 |
|---|---|---|
| `memos` | [MemTensor/MemOS@d326a641](https://github.com/MemTensor/MemOS/tree/d326a6419467c2205041b58533b0ebfdf4f38173) | Tree-text 同步处理、管理与关联；Neo4j Community 原生向量索引 |
| `mem0` | [mem0ai/mem0@84bf4681](https://github.com/mem0ai/mem0/tree/84bf468176f0c5e82493bb95aec5484eb2d92bc1) | 官方 Memory、批量抽取／向量处理、实体合并、混排、Qdrant 与 SQLite |
| `memmachine` | [MemMachine/MemMachine@377510d4](https://github.com/MemMachine/MemMachine/tree/377510d436dc81c3651502f2d5e36ff245650ce7) | 原生 library，SQLite／USEARCH，episodic、STM、summary、semantic 后台处理 |
| `emem` | [KevinSRR/EMem@4390269e](https://github.com/KevinSRR/EMem/tree/4390269ecda5ab7e3ecce0e10bf8ebfd692ec406) | 原生会话构图、索引和检索；默认无 PPR，配置启用 EMem-G |
| `memora` | [microsoft/Memora@dec3f8f2](https://github.com/microsoft/Memora/tree/dec3f8f2444eace7004fc084abe1be9f3d88270e) | 官方分段、memory builder、cue、BM25、episodic 与 prompt retrieval；无 GRPO 训练 |

EMem 对应 RAW-RAG 论文引用的长对话记忆方法，不是 EverMemOS。MemOS 与已有 `memoryos` 为不同方法；
MemOS 的 PyPI 分发名 `MemoryOS` 又与旧 MemRL 依赖冲突，必须使用独立环境。

上游源码缓存位于 `.mematlas/upstream/`；适配包内保存固定提交、源码散列和许可证。源码与方法环境
分别管理，禁止通过升级共享环境来消除冲突。各包的 `__init__.py`、`config.py`、`example.py` 和
`method.yaml` 是当前接入说明；环境锁文件以实际成功解析的环境为准，不能把未安装需求表称为锁文件。

EMem 和 Memora 使用未修改的固定源码文件，可在新 checkout 中重建缓存：

```powershell
python scripts/fetch-memory-adapter-source.py emem
python scripts/fetch-memory-adapter-source.py memora
```

脚本根据包内 `source.json` 的提交与逐文件 SHA-256 下载；再次执行只校验已有文件，遇到差异保留文件并失败。
可以用 `--destination` 指定其他源码目录，再把它填写到 `runtime.source_roots`。该脚本不安装依赖、不下载模型。
Mem0、MemOS 与 MemMachine 通过锁文件内的固定提交归档或 Git 引用安装官方包；预检查会再校验安装后的源码，
不能仅依靠相同包版本号认定实现一致。环境锁以 Windows x64／CPython 3.12 的实测解析为准，其他平台需另行解析与验证。

在已安装 Python 3.12 的新环境中，创建独立环境后安装该方法的锁文件，例如：

```powershell
py -3.12 -m venv .venv-mem0
.venv-mem0/Scripts/python.exe -m pip install -r methods/mem0/requirements-lock.txt
.venv-mem0/Scripts/python.exe -m pip check
```

其他方法同样使用各自环境，锁文件名以末尾验收表为准；不要把五份依赖合并进共享环境。MemOS 还需要已经运行的
Neo4j Community >=5.18（默认 `bolt://127.0.0.1:7687`、数据库 `neo4j`），并设置 `NEO4J_PASSWORD`；
它使用数据库内的原生向量索引，不要求另装云服务。MemMachine 使用本地 SQLite／USEARCH，无需额外数据库进程。

本机已补齐项目内的 Neo4j Community **5.26.0** 便携部署，使用现有 JDK 21，未安装 Windows 系统服务。
安装归档通过官方 SHA-256 校验；数据、日志、随机生成的本地密码均保存在被忽略的 `.mematlas/services/`。
仅监听 `127.0.0.1:17687`（Bolt）和 `127.0.0.1:17474`（浏览器），Java heap 上限 512 MiB、page cache 128 MiB。
启动／复验／正常停止命令如下；停止通过原生 JVM shutdown hooks 关闭数据库，不删除数据：

```powershell
.venv-memos/Scripts/python.exe scripts/local-memos-neo4j.py start
.venv-memos/Scripts/python.exe scripts/local-memos-neo4j.py status
.venv-memos/Scripts/python.exe scripts/local-memos-neo4j.py test
.venv-memos/Scripts/python.exe scripts/local-memos-neo4j.py stop
```

`test` 自动向子进程提供测试连接配置，只运行受控原生验收。正式接入当前本机数据库时，在运行医院的同一终端设置：

```powershell
$localNeo4j = Get-Content .mematlas/services/memos-neo4j-local.json | ConvertFrom-Json
$env:NEO4J_PASSWORD = $localNeo4j.password
.venv-memos/Scripts/python.exe scripts/memory-adapter-config.py memos --neo4j-uri $localNeo4j.uri --output memos-memory.json
```

密码不写入版本控制或生成的 Memory 配置。MemOS 上游的 `memory_vector_index` 由整个数据库共用；
本轮真实图验收使用 **1024 维**向量，与现有 Qwen embedding 配置一致。不同维度必须使用独立实例／数据库，
适配层发现已有索引维度冲突时明确失败，不覆盖索引或现有记忆。运行医院仍需实际可用的 LLM 和 embedding 服务。

## 公共流程与保存

运行 `python scripts/memory-adapter-config.py memora --output memory.json` 可生成单方法配置；方法名可替换为
上述五个 ID。脚本使用各自 `.venv-方法名` 解释器、现有本地 embedding 服务与独立运行目录，
仅写配置，不下载模型或发请求。按现有部署覆盖 `--llm-model`／`--llm-base-url`；密钥通过
`MODEL_API_KEY` 和 `LOCAL_EMBEDDING_API_KEY` 环境变量提供，MemOS 另需 `NEO4J_PASSWORD`。
接医院时把该 Memory 配置传给现有 runner，`benchmark.memory_top_k` 默认省略；正式实验参数另定。

`index()` 只描述实际可访问视图，不写入；`add(MemoryUnit)` 接收单元，receipt 不保证立即完成提取；
`search()` 使用方法原生预算；`episode_end()` 只记录任务边界。医院先结束任务再交付完整 experience／
反馈，适配层必须支持这一顺序。同任务分批内容避免重复索引累计前缀；延迟反馈保持原 scope、related refs
与完整 applied memory，不能重放已提取轨迹。完整工具结果与来源不得由适配层截断。

公共层变化：

- `HospitalOptions.memory_top_k=None` 默认保留方法预算，可显式指定正整数。旧 Mem0 suite 显式保留 5。
- subprocess 预检查在 `runtime.python_executable` 指定的 Python 中执行；只检查依赖、源码与配置，
  不构造方法／模型 provider、不 setup、不建库。禁用环境检查时显式返回 `not_inspected`。
- 内部 `_freeze()`／`_thaw()` 经 in-process、subprocess 和 service 转发，未增加 Agent 公共接口。
  快照及恢复期间暂停后台写入，嵌套冻结共用暂停；只读入口不 flush、不清空待学习队列。
  冻结、解冻或状态校验失败时防止继续不确定的写入；已检测并成功恢复的只读违规沿用既有评测重试规则。
- 子进程显式引导当前 checkout 的 Python 包，支持名称为 `MemAtlas` 的扁平目录；不复用父环境的 site-packages。
- 子进程持续收集上次响应之后的用量，包含请求之间完成的后台模型调用，避免漏计；重复查询不重复入账。
- Mem0 原生 Qdrant 本地检索会原地归一化向量，因此冻结检索采用 `snapshot` 保护。医院既有 Mem0
  并发模式兼容此保护；检索与病例结束校验共用 Memory 锁，防止数据库恢复和快照竞争。未扩展其他方法的并发授权。

外层 checkpoint schema 为 4；内部状态必须包含 native 实现身份和提交，旧检查点不自动迁移。
快照文件按内容寻址并校验，相同逻辑状态连续保存返回相同引用，避免超出子进程消息限制以及只读误报。
公共层对超过 1 MiB 的 JSON 状态自动转为 `state-snapshots/` 文件引用，worker 在接收恢复指令后校验读取，
已覆盖 17 MiB 状态的子进程往返和篡改检测。远程 service 的快照文件由远程服务持有和转运。
迁移 checkpoint 时应同时保留其引用的快照文件；恢复不得重放对话或调用模型。
医院状态指纹依据校验后的逻辑内容计算，递归处理本地 JSON 快照引用，避免新 worker／目录的位置变化
被误判为记忆变化；远程 service 使用服务端给出的校验摘要，不从客户端打开服务端文件。
子进程关闭在最后响应后继续排空输出，再限时回收；20 MB 的原生退出日志已覆盖，避免 Windows 管道阻塞。

`save()` 和 `read_only()` 不会自动 flush。公共 `Memory` 关闭时仍按既有生命周期自动 flush；
需要恢复未完成缓冲时，先保存检查点，恢复该检查点得到的是保存时的缓冲状态，而非关闭后排空的状态。

框架为写操作回滚、保存和冻结校验执行的快照属于公共运行开销，原生 add/search 的计时与这些操作分别
记录在 operation traces；正式效率比较应同时报告原生操作与完整医院流程成本，不能只选其中一种数字。

## 回归环境与验收记录

公共回归使用独立 `.venv-adapters`（Python 3.12），依赖锁见
`test/native_adapters/requirements.lock.txt`。从扁平 checkout 可运行：

```powershell
.venv-adapters/Scripts/python.exe scripts/check-memory-adapters.py test/native_adapters -q
.venv-adapters/Scripts/python.exe scripts/check-memory-adapters.py test/test_memory_interface.py test/test_memory_episode.py test/test_method_configuration.py test/evaluation -q
```

脚本为受控医院测试补充占位密钥，测试执行／传输由 fixture 控制，不加载真实模型权重或启动付费病例。
临时产物使用 `.mematlas/adapter-tests-*`，避开当前系统临时目录的访问限制。新增公共回归覆盖嵌套冻结、
冻结及恢复失败、后台暂停释放、跨进程恢复、实际解释器预检查、无 provider／DB 构造、原生检索预算。

五方法的原生验收结果如下。MemOS 首轮因未部署 Neo4j 而跳过的路径已用本机真实服务补验；
五个独立环境的 `pip check` 均通过。

`MEMATLAS_TEST_NEO4J_PASSWORD`（可选 USER／DATABASE），仅操作独占测试 namespace。
已在五个实际解释器运行 subprocess 只读预检查：源码／依赖均可用，未创建任何目标运行目录或数据库。
模型配置和占位密钥仅用于声明服务，不证明实际模型端点可用；首轮 MemOS 因未配置 Neo4j 密钥明确返回未就绪，
后续已部署并实际连接本机 Neo4j，真实验收用 `local-memos-neo4j.py test` 自动提供独立连接与密码。

公共回归复验：`test/native_adapters`、接口／任务／方法配置、`test/evaluation`、EMem／Memora 边界测试、
MemOS／MemMachine 契约测试及医院运行时回归合计 **269 通过、14 跳过**。其中契约测试使用可观测后端检查公共语义，
不能作为官方数据库或算法的原生验收；具体原生测试须在对应方法环境单独执行。

Mem0 专用环境复验：`test/mem0` **19 通过**；另 `test/test_openhospital_parallel_tests.py` **6 通过**。
覆盖固定官方实现的批量提取／实体／排序差分、完整 scope、恢复精度、跨进程零重放、医院即时／批次／
延迟反馈，以及并发病例的顺序、失败恢复和冻结污染检测。Qdrant 的本地 payload index 无效警告为上游行为；
本轮使用本地 Qdrant，不宣称验证了远程服务器索引性能。

MemMachine 专用环境复验：**6 项原生测试通过**，`pip check` 无依赖破损。覆盖 SQLite／USEARCH、
STM summarizer 与 semantic 后台处理、待处理队列冻结／恢复、医院边界先于完整经历、新 subprocess worker
零模型恢复及继续写入。保留上游 semantic 默认 5 条／5 分钟处理门槛；显式 `flush()` 为排空已接受历史
临时满足门槛，完成后恢复原参数。原生 semantic 项目／用户流异步交错，保留每条流的原生顺序，不伪造全局排序。

MemOS 补验：**6 项原生测试通过，无跳过**。使用官方 Neo4j Community 5.26.0 和未修改的 MemOS 固定源码，
覆盖真实图写入／检索、完整节点／关系属性／删除标记／向量恢复、两 scope 隔离、只读状态稳定、
跨 namespace 克隆、全新 subprocess worker 恢复零 LLM／embedding 调用以及恢复后继续写入。
医院短链验证先结束执行、后提交 experience／反馈，测试阶段保持冻结。上游文档解析器的可选依赖警告
不涉及实际使用的 chat fine reader；未使用简化数据库或重写算法来替代验收。
本次补验另重跑公共生命周期与 MemOS 契约：**23 项通过**；本地部署脚本的正常停止及保留数据重启已实测。

所有测试的 LLM／embedding 使用固定响应或本地测试 HTTP 服务；运行原生数据库和官方算法，但不代表已测临床
质量、真实 Qwen 响应质量或正式实验效率。活跃存储统计排除 `snapshots/`、`state-snapshots/`、
`adapter_snapshots/` 的恢复副本；快照时间仍记入操作 traces。
