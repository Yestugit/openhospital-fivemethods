# 现有 Memory 方法书写约束

**新方法书写要求：**
1、非常重要：不允许擅自简化逻辑来重写到框架，如果原仓库能够通过适配性改动来接入到我们的框架，那就直接接入即可，不需要重写。适应性重写入的前提是不能简化数据库存储逻辑、不能为了方便实现简化memory逻辑、不允许缺失核心机制，如果做不到，请不要重写，你这样集成的方法不是原方法逻辑，无法用来跑学术论文的对比实验，属于学术造假。你的核心目的就是，你集成进来之后的方法，能够用于跑学术论文的对比实验


4. **公共接口的用途和使用约定保持一致。**公共 Memory 接口统一为 `index`、`add`、`search` 和 `episode_end`。`index()` 查看方法提供的记忆层级或访问视图；`add(unit)` 提交一个记忆单元，一个任务可以多次提交；`search(query)` 按当前需求检索记忆；`episode_end()` 标记一次 Agent 任务结束。方法内部负责处理即时写入、缓冲、去重、反馈学习、批次更新和自动演化。——10.31
5. **方法内部处理可以不同。**例如 Mem0 可在收到记忆单元后立即写入；MemRL 可先记录相关单元，取得完整轨迹和真实反馈后再更新。Agent 继续使用同一组公共接口和原有调用位置，方法内部处理即时写入、缓冲、去重或批次更新。
6. **切换方法时保留 Agent 原有流程。**Agent 继续使用同一组公共接口和原有调用位置。方法需要的额外信息通过配置、`MemoryUnit.extensions` 或 `search(..., extensions=...)` 补充；方法内部处理算法、存储和更新差异。
6. **每个 Memory 方法和 Benchmark 提供简洁的使用清单。**说明参数、输入输出、必要数据与反馈、服务条件及原生处理规则；注明公共接口的固定用途，并说明方法所需的数据补充。必要条件不满足时阻止运行，明确缺失项；只检查实际使用路径需要的条件。——10.31
   每个 Memory 方法通过 `__init__.py` 导出配置类和必要的公共适配对象并简述使用条件，供 IDE 和 `help()` 查看；`example.py` 展示最小接入流程，`method.yaml` 保留程序声明与校验。具体编写按[方法书写约束](../方法集成/1031方法书写约束.md)执行，替换原 `usage.yaml` 和方法 README 形式。——10.31

   9. **所有可执行方法通过公共 Memory 接口接入。**不新增 Agent 调用的方法特有接口。方法差异通过配置、公共数据结构和 `extensions` 表达；方法内部的辅助函数、算法步骤和存储操作不作为 Agent 入口。——10.31

## 4. 可调用接口

下表为公共 Memory 接口；标注 `await` 的调用在异步函数中使用。`index()` 查看记忆层级或访问视图；`add()` 提交记忆单元；`search()` 按需检索记忆；`episode_end()` 标记任务结束。各方法在内部实现这些约定，方法需要的数据见其使用清单。——10.31

`detail`、`update`、`delete`、`flush`、`save`、`load`、`reset`、`read_only` 和 `stats` 仍属于公共运行时能力，是否支持由方法能力声明决定。`evolve` 不作为 Agent 公共接口；方法能够依据累计次数、阈值或内部状态自动演化时，由方法内部触发。

方法内部处理可以不同。例如，Mem0 可在收到记忆单元后即时写入，MemRL 可先缓冲相关单元，待完整轨迹和真实反馈就绪后更新；Agent 仍按相同用途和位置调用公共接口。——10.31

| 目的 | 接口 | 原本 → 改进后 |
|---|---|---|
| 方法查询 | `MemAtlas().methods()` / `MemAtlas().describe(method_id)` | 查看已注册方法、参数、能力与条件 |
| 检查 | `Memory.check(config)` | 保留入口，检查方法所需配置与条件 |
| 创建与关闭 | `async with Memory(config) as memory` | 多种创建包装 → 一个构造入口 |
| 记忆视图 | `await memory.index()` | 查看方法提供的记忆层级或访问视图 |
| 提交记忆单元 | `await memory.add(unit, episode_ref=None, scope=None)` | 提交事件、任务、输出、反馈或完整记忆单元，返回 `WriteReceipt` |
| 检索 | `await memory.search(query, level_ref=None, top_k=None, scope=None, extensions=None)` | 按当前需求执行方法原生检索，返回 `MemoryContribution` |
| 任务结束 | `await memory.episode_end(episode_ref=None, status="completed", scope=None)` | 标记任务边界，方法按自身条件完成学习或更新 |
| 查看详情 | `await memory.detail(...)` | 方法声明支持时查看记忆详情 |
| 更新记忆 | `await memory.update(...)` | 方法声明支持时更新记忆 |
| 删除记忆 | `await memory.delete(...)` | 方法声明支持时删除记忆 |
| 提交缓冲处理 | `await memory.flush()` | 方法声明支持时处理缓冲，无需在每次 `add()` 后调用 |
| 保存／恢复 | `await memory.save(path)` / `await memory.load(path)` | 状态与检查点包装 → 一套保存／恢复入口 |
| 冻结更新 | `async with memory.read_only():` | 保留记忆保护，Agent 在外部执行 |
| 清理 | `await memory.reset()` | 仅方法声明支持时可用 |
| 统计 | `memory.stats()` | 查看操作与已采集的资源用量 |

**易错点：**——10.31

1. `flush()` 仅在方法需要处理缓冲时使用；`add()` 后无需一律调用。即时写入或自动处理缓冲的方法可直接继续使用，具体要求见方法清单。
2. 方法能够根据累计次数、阈值或内部状态自动判断演化时，由内部触发；演化逻辑放入 `add()`、`episode_end()` 或内部更新流程。`flush()` 只用于方法要求的缓冲处理。
3. `save()` 用于保存当前记忆与必要运行状态，`load()` 用于恢复；学习与更新时机由方法内部决定。
4. 方法切换时，Agent 继续使用同一组公共接口和原有调用位置。额外信息通过配置、`MemoryUnit.extensions` 或 `search(..., extensions=...)` 补充，方法内部处理实现差异。
5. `episode_end()` 只标记任务边界，不推断成功、奖励或学习结果；真实评价通过 `MemoryUnit.feedback` 提交。

**记忆归属默认沿用 `config.scope`；需要切换且方法支持时，可通过调用参数 `scope` 覆盖。**`scope` 确定记忆归属，`episode_ref` 关联任务；延迟反馈沿用原单元的实际归属。

1. **记忆单元与任务衔接。**`add()` 默认由运行时自动关联当前任务。需要跨调用或提交延迟反馈时，使用 `WriteReceipt.write_ref` 或显式提供 `episode_ref`。
2. **反馈按需提供。**无需评价的方法可以直接处理经历；需要评价的方法取得真实反馈后提交。已处理事件避免重复写入，完整轨迹继续保留。
3. **提交与更新分工。**`add()` 提交记忆单元，单元可以包含事件、任务、输出、反馈、实际使用的 `MemoryContribution` 和方法所需的 `extensions`。方法根据自身规则决定何时完成学习或更新。
4. **方法差异数据。**检索参数传入 `search(..., extensions=...)`，提交数据放入 `MemoryUnit.extensions`，检索产生的方法关联信息保存在 `MemoryContribution.extensions`。稳定参数放入方法配置。

Agent 使用 `search()` 获取记忆，使用 `add()` 提交事件、输出、反馈或完整记忆单元，使用 `episode_end()` 标记任务结束。方法内部负责即时写入、学习更新、批次处理和自动演化。——10.31


# 如何给用户呈现方法配置和专有数据
更新：2026-10-31，使用包入口、配置类和公共数据结构说明呈现使用要求；演化由方法内部处理。——10.31

用于逐个整理 RiseMem 已集成的方法，让用户快速找到配置参数和专有数据，并清楚怎样使用。保留原方法的算法、存储和更新规则。
当前已接入 Memory 接口 v3 的方法：mem0、a-mem、memoryos、memrl、reasoningbank、expel、awm、memcon、ael。

方法特有数据输入使用3. **扩展：**`extensions` 按方法组织专有数据，如 AEL 的工具评价和策略记录、M2A 的直接答案。用户提供真实业务数据，方法产生的关联信息由框架保留并传回学习流程。

1. **文件组织**

   ```text
   方法目录/
   ├── __init__.py   # 用户入口：导出可用对象，简述使用条件
   ├── config.py     # 用户配置类
   ├── method.yaml   # 程序声明与校验规则
   ├── method.py     # 公共接口适配与方法内部实现
   ├── core.py       # 原方法算法、存储与更新逻辑
   ├── utils.py      # 内部辅助函数，按需提供
   └── example.py    # 最小完整使用示例
   ```

   不再要求每个方法提供 `README.md`，删除原有 `usage.yaml`。提示词、必要算法模块和上游源码按需保留，无需创建空文件。

2. **配置参数和专有数据怎样呈现给用户**

   | 用户要找的内容 | 开发人员怎样提供 | 用户在哪里查看 |
   |---|---|---|
   | 方法配置参数 | 在 `config.py` 定义配置类，写清字段类型、默认值、必填条件和含义，从包入口导出 | 打开 `config.py`，或通过 IDE、`help(配置类)` 查看 |
   | 调用时的专有参数 | 通过公共数据结构的 `extensions` 表达，按需定义简短输入类型，说明字段含义、类型、必填条件及传入位置 | 查看字段定义或说明；示例展示填写位置 |
   | 支持的公共操作 | 提供 `SUPPORTED_OPERATIONS`，复用现有能力声明 | 从包入口查询；具体参数查看公共 `Memory` |

   **`__init__.py` 是统一发现入口。**导出配置类和必要的公共适配对象。模块说明采用固定栏目：必要服务、必要数据与反馈、调用流程；简述检索返回内容如何使用，没有专有参数时明确注明。通过 `help(方法包)` 或打开文件查看。

   配置类和按需定义的输入类型使用 docstring 说明，供 IDE 和 `help()` 读取。`__all__` 列出公开对象，内部算法和工具函数不加入其中。已有 `describe()` 作为辅助查询，无需新增查询接口。

3. **用户看到的使用形式**

   例如 MemRL 的目标用法：

   ```python
   import mematlas.methods.memrl as memrl

   help(memrl)                        # 必要服务、数据和使用流程
   print(memrl.__all__)               # 可导入对象
   print(memrl.SUPPORTED_OPERATIONS)  # 支持的公共操作
   help(memrl.MemRLConfig)            # 配置参数
   help(memrl.LearnOptions)           # 提供该类型时，可查看专有输入说明
   ```

   用户据此填写配置和专有数据：

   ```python
   method_config = memrl.MemRLConfig(batch_size=8)

   # 以下两种填写方式任选一种，用于 MemoryUnit.extensions。
   extensions = {"memrl": {"task_id": 123}}
   extensions = {"memrl": memrl.LearnOptions(task_id=123)}
   ```

   类型辅助可选，按需使用 `TypedDict`，无需每个方法都建立输入类型，也无需额外声明变量。专有数据按方法名组织：检索参数传入 `search(..., extensions=...)`，提交数据放入 `MemoryUnit.extensions`，检索产生的方法关联信息保存在 `MemoryContribution.extensions`。没有专有数据时省略，公共字段直接使用。

4. **配置与接口的取舍**

   配置只公开必需项和常用覆盖项，其余沿用方法默认设置，采用特定预设时注明，不增加高级参数层。模型服务、归属和运行设置使用公共配置。配置类按框架统一方式实际使用，原生参数映射在内部完成；默认值与 `method.yaml` 保持一致，避免重复维护。

   方法差异通过配置、公共数据结构和 `extensions` 表达。内部辅助函数集中在 `utils.py`，内部算法步骤无需加入用户导出清单。

5. **完成要求与接口约定**

   `example.py` 使用真实配置、公开对象和公共接口，展示必要数据、专有参数填写位置、调用顺序及额外步骤。包说明、配置、类型、`method.yaml`、导出与实际行为保持一致，不支持的操作明确说明。用户应能通过 **包入口了解要求 → 配置类填写设置 → 最小示例完成调用** 接入，无需阅读内部适配和算法代码。

   公共接口用途和接入位置保持稳定：`index` 查看记忆层级或访问视图，`add` 提交记忆单元，`search` 按需获取记忆，`episode_end` 标记任务结束。即时写入、缓冲、去重和批次更新由方法内部处理；切换方法时，用户按需补充配置和数据。

   `evolve` 不作为 Agent 公共接口。方法能够依据累计次数、阈值或内部状态判断演化时，由方法内部触发；演化逻辑放入 `add()`、`episode_end()` 或内部更新流程。冻结评测本身不触发演化。——10.31

## 6. 测评 QA 接入约束——11.01

**1. 什么情况下需要新建 QA**

默认复用 `DefaultQA`。只有默认流程无法完成方法必需的数据准备或执行步骤时，才增加方法 QA。

| 方法需求 | 处理方式 |
|---|---|
| 配置参数不同；专有数据可通过现有公共字段或 `extensions` 直接传入；特殊处理可由方法内部完成 | 复用 `DefaultQA` |
| 需要额外采集、计算或组织方法必需的数据 | 新建方法 QA，补充必要的数据处理 |
| 必须主动调用特有操作，或采用方法自身的特殊答题机制 | 新建方法 QA，补充必要的执行步骤 |

例如，Mem0、MemoryOS 使用默认 QA；MemRL 使用 `MemRLQA` 补充任务类型及训练结束标记，答题仍复用默认流程。

**2. 怎么新建**

在 `methods/<方法>/qa.py` 中继承 `DefaultQA`，只覆盖必要步骤：

| 需要调整的内容 | 覆盖方法 |
|---|---|
| 整理检索扩展参数 | `retrieval_extensions(metadata)` |
| 调整检索调用 | `async retrieve(case, memory)` |
| 组织答题输入 | `messages(case, contribution)` |
| 提交学习前整理专有数据 | `prepare_episode(case, episode, *, last_for_scope)` |
| 默认答题流程无法满足要求 | `async __call__(case, memory)` |

`prepare_episode()` 会用于预检查和实际学习提交，应保持为纯数据整理，避免在其中调用模型、写入记忆或触发更新。`last_for_scope` 表示当前归属的最后一个训练单元，用于方法确有需要的结束标记。

在现有方法插件类中声明：

```python
qa_factory = "mematlas.methods.<方法>.qa:方法QA类名"
```

框架自动选择该 QA；未声明时使用 `DefaultQA`。普通测评用户继续配置 `answer_model`，无需自行编写或选择 QA。

**3. 完成要求**

QA 统一返回 `MemoryEpisode`，保留实际轨迹、输出及实际使用的完整 `MemoryContribution`。历史导入、学习提交、冻结、评分和恢复继续由实验层处理，QA 避免重复实现。

方法 QA 不读取测试参考答案生成回答；必需数据无法取得时，明确说明缺失条件。新增 QA 后验证数据传递、必要步骤和记忆使用，并在方法包说明中简述其作用。

## 7. 专有数据与数据结构的增设约束——11.01

**1. 什么情况下增加专有数据或数据结构**

先检查公共字段能否表达。任务、轨迹、输出、奖励、反馈等已有公共字段直接复用；稳定参数放方法配置。只有方法核心机制需要额外信息，且公共字段无法表达时，才增加专有数据。

简单字段通过 `extensions` 传递；内容确实复杂时，再由方法定义专用结构，避免重复定义已有公共数据。

**2. 专有数据的固定格式与定义要求**

专有数据按方法 ID 组织：

```python
extensions = {
    "方法ID": {
        "字段名": 实际值,
    }
}
```

| 数据用途 | 传入位置 |
|---|---|
| 事件附加数据 | `MemoryEvent.extensions` |
| 检索条件 | `search(..., extensions=...)` |
| 提交数据 | `MemoryUnit.extensions` |
| 检索产生的方法关联信息 | `MemoryContribution.extensions` |

每个字段统一说明：**含义、类型、必填条件、默认行为、数据来源和所属操作**。按需用 `TypedDict` 等类型表达，输入校验与 `method.yaml` 声明保持一致。

用户提供真实业务数据；方法产生的关联信息随完整 `MemoryContribution` 保留，并通过 `MemoryUnit.applied_memory` 回传方法内部学习流程。
