# 方法集成问题与框架改进记录

本文件专门记录方法集成过程中发现的两类问题：

1. 普通测评 QA 无法提供方法所需输入或执行步骤，需要新增并注册方法专用 QA。
2. Memory v2 或统一测评框架无法直接表达方法原生能力，需要修改框架、增加扩展点，或记录外部阻塞。

本文件记录的是问题闭环，不以“代码已经提交”为完成标准。每条记录必须包含发现现象、影响范围、处理方式、验证证据和剩余限制。不得在此记录 API key、token、cookie 或其他凭证。

## 一、专用 QA 问题

| 编号 | 方法 | 发现的问题 | 原因 | 处理 | 状态与证据 |
|---|---|---|---|---|---|
| QA-001 | ReasoningBank | 原生训练需要 `task`、完整 `trajectory` 和外部真实 `success`；普通 `DefaultQA` 只有问答答案流程，不能提供这些字段，也不能从参考答案伪造成功标签。 | ReasoningBank 学习的是成功/失败轨迹经验，不是普通检索问答。 | 新增 `methods/reasoningbank/qa.py:ReasoningBankQA`，保留轨迹和外部标签；在 `methods/reasoningbank/method.py` 注册 `qa_factory`。 | 已解决。`benchmarks/check_qa_registration.py`、`benchmarks/check_reasoningbank_trajectory.py` 通过。 |
| QA-002 | AEL | 原生路径需要 ticker、sector、market regime、prediction/actual、tool evaluations 和数值 outcome/reward；普通 QA 无法组织完整金融结构化输入。 | AEL 的 controller、bandit 和 usefulness 更新依赖结构化字段及数值反馈，不能用普通文本答案或布尔 success 替代。 | 新增 `methods/ael/qa.py:AELQA`，传递 `extensions["ael"]` 结构化字段和 numeric `outcome_score`；在 `methods/ael/method.py` 注册 `qa_factory`。 | 已解决。`benchmarks/check_qa_registration.py`、`benchmarks/check_ael_portfolio_slice.py` 通过。 |
| QA-003 | MemCon | 原生方法需要 `EPISODE_START -> ACTION -> OBSERVATION/TOOL_RESULT` 事件流、任务上下文和真实 episode success；普通 QA 不能生成或组织动作-观察配对。 | MemCon 学习 G-Memory 和 policy，不是单轮问答记忆。 | 新增 `methods/memcon/qa.py:MemConQA`，传递任务、检索限制和 native contribution；在 `methods/memcon/method.py` 注册 `qa_factory`。 | 已解决。`benchmarks/check_qa_registration.py`、`benchmarks/check_memcon_action_observation.py` 通过。 |

## 二、框架设计问题

| 编号 | 发现的问题 | 影响 | 处理方式 | 状态与证据 |
|---|---|---|---|---|
| FW-001 | 原有默认 QA 把答案模型视为必需依赖，无法直接运行不需要生成答案的 native trajectory、portfolio 或 action-observation benchmark。 | 方法专用 benchmark 即使能直接计算 native 指标，也会在 QA 初始化阶段失败。 | 增加 `DefaultQA.requires_answer_model_for()`；方法 QA 可声明 native profile 不需要答案模型。 | 已解决。三个 native slice 均可通过统一 `ExperimentRunner` 执行。 |
| FW-002 | `ExperimentRunner` 原先按文件路径理解 benchmark，无法自然承载代码内置且由方法专用 QA 直接评分的 benchmark。 | 新增 native benchmark 需要绕过普通数据文件入口，容易退回用户 Agent 临时脚本。 | 扩展内置 benchmark factory 和 runner，使无路径 benchmark 进入统一生命周期，并保留 native metrics。 | 已解决。AEL、MemCon 的统一实验结果为 `failures=()`；ReasoningBank trajectory slice 通过。 |
| FW-003 | 公共 QA/episode 合同没有为方法专用的结构化输入预留固定字段。 | 强行修改公共模型会把金融字段、动作观察字段等方法差异扩散到所有方法。 | 使用 `MemoryEpisode.extensions["ael"]`、`MemoryEpisode.extensions["memcon"]` 等方法命名空间；QA 只补充必要字段。 | 已解决并已在三种方法中使用。需要继续保持命名空间隔离。 |
| FW-004 | 框架公共层不能替代完整原生 Agent、远程 memory service、环境执行器和外部 benchmark 依赖。 | 当前可以验证 Memory v2 生命周期和方法核心逻辑，但不能声称已复现完整 WebArena、SWE-Bench、ALFWorld、PDDL 或金融 Agent。 | 保留方法核心 adapter；把完整 Agent、环境、远程后端列为外部依赖和未覆盖项，不伪造 benchmark 结果。 | 未解决，属于运行环境/外部集成边界。详见“剩余阻塞”。 |

## 五、2026-11-02 保真复核结果

本节是对 `ReasoningBank -> AEL -> MemCon` 迁移代码与只读上游源码的二次人工核对。native slice 通过只说明接口和生命周期可运行，不等同于原生算法全量保真。

| 编号 | 方法 | 复核发现 | 严重程度 | 当前结论与处理 |
|---|---|---|---|---|
| FID-001 | ReasoningBank | 上游将模型输出按空行拆分后原样保存；旧集成版 `parse_notes()` 强制 1--3 个完整 `Title/Description/Content` 区块，并将整段 output 作为一个 episode group 返回。 | 中 | **已部分修复。**现在按上游空行拆分并逐 note 返回，所有 note 保留同一 `group_id`；标题字段只做 best-effort 解析，不再因格式偏差拒绝学习。仍保留 episode 级相似度选择。 |
| FID-002 | ReasoningBank | embedding 从上游 Google/Qwen embedding 换成框架注入服务。 | 中 | 属于允许的服务替换，不是方法流程改写，但会改变向量空间和效果；完整 benchmark 前必须固定模型、维度并记录。 |
| FID-003 | AEL | 原始默认 planner 为 `sequential/decompose/adaptive`，旧集成默认只有 `sequential`；`method.yaml` 没有 `planner_names` 配置字段。 | 中 | **已修复配置层。**默认恢复 3 个 planner 臂，并把 planner/tool/memory policy 名称暴露到 `AELConfig` 和 manifest。当前 adapter 仍只承接 memory/controller，不执行完整 planner Agent。 |
| FID-004 | AEL | 旧集成 `learn()` 固定使用 `uniform_credit()`；原始默认 credit 方法为 FCC。 | 高 | **已部分修复。**增加 `credit_method` 配置，portfolio rich episode 可走 `portfolio_credit`，generic episode 可选 structural/uniform；完整 FCC 仍需要原生 Agent trace、baseline 和 counterfactual 输入，不能声称已完全恢复。 |
| FID-005 | AEL | `methods/ael/native/evolution/reflection.py`、`credit.py` 和 `memory/store.py` 原先引用被删除的 `native.llm_utils`；`credit.py` 还引用被删除的 `native.evolution.loop`。 | 高 | **已修复悬空 import。**补充可选 `llm_utils` bridge，并将工具方向提取逻辑移到本地 credit 模块；无 `litellm` 时只有实际调用 LLM 路径才报可解释错误。完整 reflection/LLM credit 仍未接入 adapter。 |
| FID-006 | AEL | 上游 nightly evolution 还包含 reflection、planner/tool 演化和 skill 处理；集成 `nightly_memory` 只保留 distill、promote 和清理 override。 | 中 | 这是明确的集成范围裁剪，不是接口错误；必须在使用说明和验收结论中称为“memory layer only”，不能声称复现完整 AEL Agent。 |
| FID-007 | MemCon | 旧集成默认 `MemConNative` 使用 lexical score、固定 top-k 和字典 reward；上游使用 embedding/G-Memory、MDP policy、UCB action、LLM key-step/failure extraction、insight backward 和 Q-learning 更新。 | 严重 | **已部分改进。**fallback 现在有可观测 action specs、UCB 风格选择、计划泛化、折扣 episode credit 和 q-value/visit 状态；仍不是上游 Chroma embedding、LLM G-Memory 或完整 MemConWrapper。 |
| FID-008 | MemCon | 旧 adapter 读取 `memory._mdp.get_episode_actions()`，但 fallback 没有 `_mdp`，异常被吞掉，导致 `native_action` 永远为空。 | 高 | **已修复。**fallback 增加兼容 MDP action history，`native_action` 可观测并参与 episode credit；完整上游 MDP 状态仍未覆盖。 |
| FID-009 | MemCon | 注入原生后端的 save/load 只探测 `snapshot/export_state` 和 `restore/import_state`；上游 G-Memory/MemConWrapper 没有该统一协议。 | 高 | **未解决。**仍需要 compatibility shim 负责导出/恢复 G-Memory、policy、MDP 和 task context。当前 fallback 自身的 policy/MDP/plans 已纳入 snapshot/restore。 |
