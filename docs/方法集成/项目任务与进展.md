# 方法集成：项目任务与进展

## 1. 已明确的任务

本方向的任务是筛选有代表性的 Memory 方法并完成接入与使用说明：复用框架公共接口，保留方法原生算法、存储和更新规则；按实际支持情况说明配置、输入、反馈及调用要求。

1. **筛选实际接入范围。**结合方法代表性、社区比较价值、可用条件和接入成本确定后续迁移对象；目录注册数量不代表都要作为当前可用方法。
2. **完成迁移与使用说明。**通过 Memory v2 公共接口承接方法能力，保留原生算法、存储和更新时机；说明方法特有的数据与必要适配。
3. **按目标场景验证。**对确定参评的方法提供可运行配置，并与 Benchmark 或 OpenHospital 流程联调。

## 3. 待解决事项与处理要求

| 事项 | 已明确的处理要求 |
|---|---|
| 确认后续迁移范围 | 依据代表性、比较价值、依赖条件与接入成本确定下一批方法；不以注册清单作为必须全部迁移的承诺 |
| 完成 v2 迁移 | 将选定方法的运行接口和能力声明迁移到 Memory v2；迁移前保持可发现状态，不标为可执行 |
| 说明原方法差异 | 对已迁移方法记录采用版本、输入、提示、学习流程和存储适配，并说明必要差异 |
| 提供可运行配置 | 为实际参评的方法提供配置、必要模型与依赖，交给 Benchmark 或 OpenHospital 联调 |
| 验证目标流程 | 检查选定方法的检索、反馈、更新、保存／恢复及冻结行为，按其声明验证支持范围 |
| 补齐逐方法使用清单 | 已完成 6 种；其余方法完成 v2 迁移后，按下方格式补充参数、接口、输入、时机和使用条件。——11.03 |
| 配合条件检查 | 为已迁移方法声明必要输入、反馈、服务与能力要求；未迁移方法不宣称具备公共层可执行检查。——11.01 |

**逐方法使用清单的编写要求：**每个已迁移到 Memory v2 的方法简洁列出以下内容，突出必需与可选项，减少重复说明和内部实现细节。——10.30

| 内容 | 必要说明 |
|---|---|
| 参数 | 含义、类型、必填项与默认值 |
| 可调用接口 | 支持的共性接口、特有接口及输入输出 |
| 调用要求 | 必需步骤与调用时机，包括原生更新边界 |
| 使用条件 | 所需数据、轨迹、反馈、模型、依赖与运行能力 |
| 最小示例 | 一条满足条件的接入流程 |

最终参评名单与逐方法完成情况在确定迁移范围并完成联调后更新。

其余使用清单与条件检查随方法迁移补齐。公共接口用途保持一致，方法内部处理算法差异；用户按清单补充必要数据，只有公共接口无法承载核心操作时才增加少量特有接口。——11.01

## 2026-11-02：ReasoningBank、AEL、MemCon v2 迁移

按 `ReasoningBank -> AEL -> MemCon` 顺序完成三种方法的 Memory v2 包迁移。三者均提供
`__init__.py`、`config.py`、`method.py`、`method.yaml`、`example.py`，旧 v1 实现和对应旧
检查夹具已删除；公共入口使用 `MemoryEvent`、`MemoryEpisode`、`MemoryContribution`。

- ReasoningBank：真实 `success/task/trajectory`、成功/失败 extraction、任务 embedding 相似度、episode note 分组、scope/source event、去重、save/load/reset。
- AEL：episodic/semantic/procedural、结构化 relevance、controller/bandit、numeric reward、usefulness、distill/promote、nightly commands、NumPy RNG 状态。
- MemCon：EPISODE_START、ACTION/OBSERVATION 配对、pending action、G-Memory success/failure/insight、policy backward、scope reset、持久化。

确定性 v2 回归脚本位于 `test/reasoningbank/check_reasoningbank.py`、`test/ael/check_ael_v2.py`、
`test/memcon/check_memcon_v2.py`，均通过；另已完成 `qwen-flash` 最小真实 Agent 联调。

已补充三种方法的代表性 native benchmark slice、统一 `ExperimentRunner` 验证和专用 QA 注册：
ReasoningBank 的 trajectory slice、AEL 的 D-full/portfolio slice、MemCon 的 ALFWorld/PDDL 风格
action-observation slice 均通过，native 指标为 1.0，且 AEL/MemCon 的统一实验 `failures=()`。
三个插件均声明 `qa_factory`，专用 QA 测试 6 项通过。完整上游 benchmark 仍待具备原始环境、数据、
模型和依赖后运行；slice 结果不等同于论文全量效果复现。详细原生逻辑核对、适配性判断、依赖阻塞与
未覆盖项见实验日志。二次保真复核后已完成第一轮插件层改进，但 AEL 完整 FCC/Agent reflection、MemCon 上游 G-Memory/MDP/Chroma 后端以及全量原生 benchmark 仍未覆盖；详细状态和证据见[问题与框架改进记录](问题与框架改进记录.md)的 FID-001--FID-009。在这些限制关闭前，不应把三种方法表述为完整原生复现。
