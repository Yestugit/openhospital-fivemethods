## 4. 2026-11-02：ReasoningBank Memory v2 迁移

**方法与原始依据。**完成 `reasoningbank` 的外部 success 反馈、单轨迹变体迁移。原始源码为
`plan/源码/ReasoningBank`，Git revision `ed80611788292ea739f1effd31f16c53823b8a0d`；对照了
README、`WebArena/induce_memory.py`、`WebArena/prompts/memory_instruction.py` 及原有单轨迹适配。
原实现中的成功/失败 extraction prompt、严格 1--3 个 Markdown note 校验、任务查询 instruction
前缀、按任务 embedding 相似度选择和一个 episode 的 note 组返回均保留。WebArena/SWE-Bench 是原生
benchmark；LoCoMo/LongMemEval 只提供问答历史，缺少真实 success 与 agent trajectory，因此不直接
作为该方法的学习 benchmark。

**迁移范围。**删除旧 v1 `methods/reasoningbank/core.py` 的 v1 适配，重建 `__init__.py`、`config.py`、
`method.py`、`method.yaml`、`prompts.py`、`example.py`。公共接口为 `observe`（no-op）、`retrieve`、
`learn`、`reset`、`save`、`load`；manifest 为 `interface_version: 2`，不再声明 `commit`、
`save_state` 或 `load_state`。`learn` 只接受真实 `episode.success`、`episode.task` 和由
`episode.events` 构成的非空 trajectory；重复 episode identity 去重，scope 与 source event IDs
保留在 native state 和返回 item 中。`storage_path` 继续写入 JSON native snapshot，save/load 包含
完整 groups，reset 只清理目标 scope。

**确定性链路验证（离线 smoke）。**使用注入的固定 extraction LLM、`implementation_mode=offline`
和临时 storage，观察初始空库、retrieve 空结果、learn 后的 note group、排序 score、memory_id、
source_event_ids、scope 及 save state；同一 episode 重复 learn 不增加 group。另验证了包导入和
`MemAtlas().describe("reasoningbank")` 返回 `interface_version=2`，且无旧 v1 类型导入。
离线 embedding 仅用于确定性回归，不代表原方法效果。

**真实 Agent 联调与未覆盖项。**已使用 DashScope OpenAI-compatible 接口的 `qwen-flash` 和
`text-embedding-v4` 完成最小真实链路：Agent 回答 395 字符，ReasoningBank 提炼 3 条 note，
随后检索返回 1 个 episode group，score 为 0.8019。未集成 self-judge、parallel/sequential MaTTS
及原始 WebArena/SWE-Bench 全量 benchmark。

## 7. 2026-11-02：代表性 benchmark 与专用 QA 补齐

针对验收要求补充了可复跑的 native benchmark slice，并把三种方法的专用 QA 接入统一
`ExperimentRunner`。这些 slice 用原方法需要的输入和评分边界验证适配正确性，不等同于论文的全量
效果实验。

**专用 QA 判断与注册。**普通 `DefaultQA` 只适合“检索后调用答案模型”的问答。ReasoningBank 的
原生训练需要 `task + trajectory + 外部 success/failure`，AEL 需要 ticker/sector、prediction/actual、
tool evaluations 和 numeric reward，MemCon 需要 action/observation 配对、任务上下文和外部 success。
因此新增并注册：

- `methods/reasoningbank/qa.py:ReasoningBankQA`：native trajectory benchmark 跳过答案模型，保留外部标签和完整贡献；普通 QA 仍复用默认路径。
- `methods/ael/qa.py:AELQA`：传递结构化金融字段和 numeric `outcome_score`，不把 bool success 当 reward；portfolio slice 可无答案模型直接评分。
- `methods/memcon/qa.py:MemConQA`：传递任务与检索限制；action/observation slice 直接返回 native contribution。

三者均通过 `qa_factory` 注册，`test/evaluation/test_method_qa_adapters.py` 共 6 项通过。

**代表性 benchmark 结果。**

| 方法 | 适配 benchmark | 规模 | native 结果 |
|---|---|---:|---|
| ReasoningBank | WebArena/SWE-Bench 形状的 trajectory slice | 3 train / 3 test | trajectory recall 1.0；success label accuracy 1.0；source provenance 1.0 |
| AEL | checked-in AEL price data 的 D-full/portfolio slice（AAPL、NVDA、JNJ） | 12 train / 1 test | episodic recall 1.0；rich tool ground truth 1.0 |
| MemCon | ALFWorld/PDDL 形状的 action-observation slice | 2 train / 2 test | label recall 1.0；source provenance 1.0 |

执行命令分别为：
`PYTHONPATH=/home/lzy/project .venv/bin/python benchmarks/check_reasoningbank_trajectory.py`、
`benchmarks/check_ael_portfolio_slice.py`、`benchmarks/check_memcon_action_observation.py`。
另外 AEL 和 MemCon 已通过统一 `ExperimentRunner` 生命周期，`failures=()`，native 指标均为 1.0。
